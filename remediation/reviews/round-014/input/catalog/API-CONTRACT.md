# Catalog administration contract 1.4

This specification and `contracts/openapi.json` describe an administration API; no listener, Android bridge or HTTP handler is implemented. The offline reference models and fixture databases test contract rules. The corrected storage baseline is 1.2.0 (`user_version=3`). Prior release migrations are evidence under `../evidence/`; do not run the corrected baseline on an existing database. `tooling/migrate_v3.py` performs a checked offline copy migration to a new file. Original files remain intact.

## Identity and authority

`entry_id = binding_id = lowercase SHA256(UTF8(canonical_signature))`. Canonical signatures are language-prefixed source signatures defined in README, with parser-normalized types and no source/version prefix. They are not erased JVM identities. One signature in two sources has one identity and two immutable occurrences. Permission changes create declaration revisions, not new IDs. A parser canonicalization change requires an explicit identity-version migration and reviewed grant invalidation; it cannot silently retarget grants. Local additions use exactly the same derivation. Imported ID/signature mismatch is a rejected import.

The three authorities are distinct: declared permission AST and provenance; OS runtime/backend capability; MCP client's exact binding/schema grants. CRUD changes metadata only. All generated/generic/known raw routes resolve to one canonical binding plan and policy evaluator; entry-point grants may restrict it. Known raw transaction requests must decode and validate under that schema or reject. Unknown raw requests require separate explicit broad backend/service authority and are visibly unable to enforce unknown method semantics; ordinary binding grants never imply it. Each alias carries exact schema hash, target and argument mapping hash, rechecked at admission. Unknown formats, codecs or required semantics remain visible and unavailable.

## Registry state and publication

SQL and JSON use `state` with staged, validated, rejected, published, retired. Create starts staged. Validation moves staged to validated or rejected. Rejected is terminal; correct bytes require a fresh immutable import ID. Publish accepts validated only, and atomically retires the old published registry, rebinds effective declarations, rebases overlays, records history/audit/outbox, increments registry generation, changes active pointer and invalidates affected approvals/schema grants. Only one published active registry is permitted by the service transaction. Re-publishing an already published registry under the same idempotency key returns the recorded result; a different key/current-active mismatch is 409. Retired cannot republish. Publication failure rolls back all changes, including generation. An import adds no active entries until publication. Validation never marks incomplete coverage complete.

Idempotency records are scoped by authenticated admin principal plus operation and key; retain request hash, response status/body and selected resource. Same canonical request hash replays original result; reuse with different hash is 409. Stage/import verifies hashes, source provenance, identity derivation, schema major/minor support, FK/count integrity and coverage declaration before validation. No network path or arbitrary filesystem path is accepted from a caller; local_artifact_id refers to a locally registered bounded artifact.

## Strong ETags, CAS and pagination

One strong ETag for all current entry representations is quoted `cat1:<registry_generation>:<imported_record_sha256-or-local>:<entry_id>:<overlay_revision>:<state>`. Base rows use overlay revision 0 and state active. Hash is the canonical effective imported document hash before local changes; local entries use literal `local`. Registry generation changes whenever the selected immutable base changes. Every overlay write MUST increase that entry's revision, including state-only transitions, and append history in the same transaction. Thus any effective representation change changes this ETag. Direct SQL overlay edits outside the administration transaction are unsupported. Canonical JSON is UTF-8, sorted object keys, compact separators, no NaN/Infinity; accepted schemas disallow ambiguous nonfinite values. No weak tags, wildcard or list preconditions.

GET by ID returns current ETag, including tombstone 410. Conflict GET is 200 with `state=conflict`, variants/base evidence and current ETag; it is never invocable. History GET is 200 with immutable history and **the current administrative ETag**, not a historical revision token. History entries' revisions are evidence only. Unknown ID is 404 without ETag. PUT/DELETE use that same current ETag even in conflict/tombstone states. Authentication/scope checks precede existence disclosure. Missing If-Match returns 428 before generic header validation; malformed precondition returns 400; stale tag returns 412 with current ETag, then transition-specific checks. This ordering is invariant across states.

Every overlay mutation increments global overlay_generation in its transaction. Search cursors pin `(registry_id,registry_generation,overlay_generation,query_hash,last_entry_id)` and expire with 410 if either generation changed; mutable overlays are never paginated as if they were an old snapshot. Reissue the query from the start after expiry. Cursors are opaque authenticated bounded tokens, tied to the principal/query and expiry; tampered tokens are 400. Order is lexical entry_id. First and subsequent page reads pin the tuple in one read transaction. Search omits suppressed/deleted/conflict by default; administrative `include_suppressed=true` includes all three with state and ETag. Invocation discovery always omits them. A returned metadata page confers no grant.

## Entry transitions

| Current state | GET | POST same canonical ID | PUT with current tag | DELETE with current tag |
| --- | --- | --- | --- | --- |
| Missing | 404 | local active, revision 1 | 404 | 404 |
| Imported active, no overlay | 200 | 409 | active overlay revision 1 | suppressed overlay revision 1 |
| Local active | 200 | 409 | active revision +1 | deleted revision +1 |
| Imported override active | 200 | 409 | active revision +1 | suppressed revision +1 |
| Suppressed imported | 410 | 409 | restore active revision +1 | idempotent 200, unchanged revision/tag |
| Deleted local | 410 | 409 | restore active revision +1 | idempotent 200, unchanged revision/tag |
| Conflict | 200 | 409 | only explicit reviewed resolution against current base hash; otherwise 409 | 409 until resolved |

PUT never changes canonical ID or signature. `x-resolution` is required only for conflict: `{action: "rebase", expected_imported_record_sha256: "<current hash>"}`; null hash means the base is absent and explicit retain-local is selected with `action: "retain-local"`. A base-absent conflict resolves to a local active entry with the same ID; it must keep prior imported provenance in history, not a dangling imported FK. Invalid resolution or changed base returns 409; schema failures return 422. Restore requires a complete validated replacement Mutation, never an empty PATCH. A local addition followed by import of the same signature is always marked conflict during publication even if bytes happen to match. An import followed by local POST is 409. Neither path silently replaces or merges provenance. Upstream unchanged base preserves overlay; changed/missing base marks conflict, including suppression tombstones, so deletion intent and evidence remain auditable. No physical imported/history deletion occurs in CRUD.

Local override documents preserve reserved identity/provenance fields; API accepts only Mutation fields and constructs origin/state/registry_version/revisions itself. Sources and raw imported evidence are never editable via PUT. Imported provenance cannot be fabricated by local clients. Admin authentication uses a separate owner-authorized scope; ordinary MCP device grants cannot call this API. Concurrent compare/update happens inside one BEGIN IMMEDIATE transaction with an affected-row/CAS check and audit/history append before commit. Unknown schema major/required semantics returns 422. All failures leave state/generations unchanged.

## Deliverable boundary and coverage

The generator emits a searchable complete inventory of acquired declarations, including unsupported/unreachable entries and reasons. It does not assert universal discovery of private/OEM surfaces. AIDL ordinals and declared method IDs are evidence, never wire transaction codes without generated/compiler proof. Public binding/permission coverage is measured against source inventories by namespace/version/kind and unresolved records; absent annotation is unknown. Source task owns acquisition/current production imports; release-002's 135,508 records and earlier pre-import 0 records are different frozen states. Source completeness remains an overall acceptance blocker until an independent current review establishes otherwise. Namespace/package modules plus global indexes/permissions/types/evidence/overrides remain a proposal; no semantic re-sharding is performed here.


## Registry and identity implementation details

The corrected schema supports several immutable registries in one database through registry_entries(registry_id,entry_id). effective_entries is an active-registry view, not a mutable/stored document or ETag table. Builder input must contain catalog.registry_version (positive monotonic publication number), android_version, api_level and coverage; each source explicitly supplies api_level (null when unknown) and channel. A new standalone release seeds registry_generation from registry_version. The serving publisher rejects a new registry_version not greater than its active version, except exact idempotent replay. Cursor tokens also include registry_id, so replacement of a file or a selected source set cannot revive an old cursor. In-database switches increment generation atomically. The builder only publishes its private staging database after all gates; transient staged pointers in that private file are never exposed to serving readers.

idempotency_records is the sole administration replay store, keyed by verified principal, operation and key. legacy_import_jobs contains unscoped historical prototype receipts copied from storage v2; these can never authorize replay of an authenticated API operation. registry_events and registry_outbox preserve publication/approval-invalidation evidence. The bridge and catalog DDL coexist in one transaction domain for serving publication. Storage user_version2 is the immutable original release-002 baseline; v3 is created only through a checked offline copy or a new build.

Dispatch manifests carry schema_hash (canonical identity, kind, arguments, return type and codec identity/status), permission_hash and document_hash separately. Provenance-only additions leave schema_hash stable. Publication still invalidates grants and approvals for changed permission_hash, required semantics, argument mapping, backend authority or target constraints even when schema_hash is unchanged: delete/disable the affected client binding rules in the same policy-revision transaction before the new mapping becomes usable. No document or metadata edit grants authority.

External annotation permission_relations.line is a one-based XML item ordinal, not an XML source line; raw_annotation preserves original item name, archive member and annotation values through annotation_evidence locators. Malformed XML is retained as an annotation-xml issue and the source report becomes partial. Declaration/parameter/unmatched annotation cases are fixture-tested. Unknown/unsupported semantics remain noninvocable.

Current source evidence identity scheme3 hashes an acquisition object (URL, revision, SHA-256, retrieval timestamp, path, API applicability, channel, kind, license and scope) plus a processing fingerprint of the extractor, parser helpers and Entry/permission contracts. source_details records x-source-identity-version=3 and x-processing-sha256. A parser correction therefore creates new immutable derived-evidence occurrences without fabricating a retrieval time or overwriting an earlier declaration. Stable binding/entry IDs remain independent of acquisition and processing identity. Historical source schemes1/2 remain preserved by copy migration. Registry IDs hash both source-set identity and explicit catalog metadata.

Canonicalization scheme2 reserves `java:package:<qualified-name>` for package inventory nodes, avoiding collision with `java:<qualified-type>` when one source set contains both a type and an identically named package. Type/member source signatures retain their existing form. This is an explicit canonicalization correction: old immutable catalog documents and hashes remain untouched, old package overlay/grant keys are not automatically aliased or retargeted, and publication must quarantine any identity-kind ambiguity until owner reconciliation. Package nodes are discovery-only and never executable. `test_package_and_type_have_distinct_identity_namespaces` reproduces and guards the collision.

When an upstream base entry disappears and no overlay exists, it is absent from the new selected view rather than a synthetic conflict. Its old registry/declaration evidence remains immutable. Existing local changes or suppression tombstones instead enter explicit conflict on changed/missing base. Registry identity/document validation must complete before any selected-view mutation; rejected publication preserves pointer, entries and cursor generations.


## Publication/storage enforcement and aggregation

Only one registry may be published. active_registry has immediate admission triggers and a deferred composite FK to the published registry state; retiring the old registry and selecting the new one occur in a single transaction, so a retired pointer cannot commit. The builder validates private registry_entries before publishing and installs its active pointer only afterward. Every overlay revision has a deferred FK to the same entry_history revision, forcing history presence at commit; JSON validity is checked in storage and full Entry/Mutation schemas are checked by the service. Active local/import collisions must become explicit conflicts before pointer publication; runtime discovery joins overlays by stable entry_id and never emits duplicate IDs. Failed publication rolls back entries, state, pointer, history and generations.

The permission aggregate is positive declared-evidence discovery, not a universal claim for every source version or an OS grant. A plain absence of a recognized annotation is excluded when selecting a single positive requirement; it is never explicit-none. In mixed positive/absent or differing-evidence cases, extensions.permission_variants retains each AST with x-occurrences and x-absence-of-annotation where applicable. Invocation still resolves the exact target/source/schema and live OS authority; it may not infer no permission from absence or use the aggregate to widen client grants. An unresolved/conflicting positive expression makes the aggregate unknown.

RawGrant.schema.json is the closed scope-only contract for constraints_json (allowed_targets, allowed_handles, allowed_displays, max_items). Connection/descriptor/code range/flag mask/hash/effect live only in SQL columns; duplicate keys in constraints_json are rejected. ImportRequest carries registry_version and coverage before staging validation. Generated aliases and binding.invoke share policy_tool_id binding.invoke; wrappers retain additional restrictive rules.


Pointer admission rejects active or suppressed imported overlays whose base_record_hash is missing or differs from the target registry entry. The publication transaction marks those overlays conflict and appends history before selecting the new pointer; tombstones are included. User Mutation.reason is stored in entry_history_reasons and returned as HistoryEvent.reason (legacy/system absence allowed). The sidecar shares entry/revision FK and is append-only; the service inserts both rows in the same transaction. A null Registry.api_level means unknown applicability, not an inferred API level. permission_reader.read demonstrates future-node quarantine while builder-generated ASTs remain strictly validated.

## Startup device-resolved bindings and types (additive contract 1.3)

`DeviceResolution.schema.json` specifies internally collected facts, inventory variants, resolved rows and immutable snapshot headers. The offline `device_resolution.py` is an executable reference over fixture facts; no device collector, Android Binder engine or HTTP service is implemented here. The complete versioned inventory is retained even when an entry is unavailable or unknown on the connected device. Historical/future SDK records must therefore be retained as inventory evidence; the existing current-target SDK-index projection is insufficient as the sole resolver input. Full production import of the normalized availability metadata remains an explicit release gate.

The collector records platform major/minor separately from SDK extension levels, OEM/build identity, observable installed module versions and supported interface version/hash/reachability evidence. It must not infer a minor version, extension, private interface or permission grant from an API major alone. Denied/unreachable/unsupported probes produce unknown; authoritative absence produces unavailable. Source-backed applicability alternatives are OR clauses, each containing AND predicates. Binding and type variants use the same evaluator. An unresolved possible variant with incompatible schema or dependencies keeps selection unknown. Type dependencies must name available type rows with the exact selected schema hash; missing or conflicting types cannot silently select a codec. Known recursive type components are resolved consistently. Availability is separate from OS/backend authority and MCP client policy, which are rechecked before dispatch.

`GET /v1/catalog/device-views/current?profile_id=...&target_key=...` returns a bounded status/header and an ETag. Before first activation the header is null and view generation is zero; this bootstrap state still has a valid ETag. `GET /v1/catalog/device-views/{view_id}` returns the immutable small header, not the entire inventory. `GET /v1/catalog/device-views/{view_id}/entries` returns at most 500 rows with all/available/unavailable/unknown filtering. A cursor binds the immutable view, authorized reader, profile/target, filter and page boundary; invalidation or expiry returns410. Historical headers remain evidence and cannot authorize dispatch. Authorization is checked before disclosing existence or scope.

The current-view strong ETag is `"dv2:<scope_sha256>:<view_generation>:<capability_epoch>:<catalog_generation>:<overlay_generation>:<inventory_sha256>"`. `scope_sha256` hashes the canonical JSON array `[profile_id,target_key,android_user_id,backend_instance_id,device_instance_id]`; it is an opaque scope identity, not credentials. Counters are decimal nonnegative integers bounded by the schema. A stale view has the new epoch and therefore a different token even before the replacement activates. `POST /v1/catalog/device-views/refresh` is restricted to the authenticated local owner and a configured profile/target. It accepts only that profile/target and one exact strong If-Match from the current-status read, never asserted facts or arbitrary probe instructions. After authorization, missing/malformed/mismatching preconditions return428/400/412 respectively, including the generation-zero bootstrap. A matched request atomically invalidates admission and queues the bounded internal refresh, returning202 with current status. Repeated or concurrent requests must re-read the new token; none can activate a snapshot built for an old epoch.

Startup, reconnect and relevant device/build/module/extension/interface/backend/catalog changes invalidate the selected view. Capture, resolution, dependency validation and hash sealing happen against one fact epoch and pinned catalog/overlay generation. Publication is a single SQLite transaction comparing the scope, current generation, epoch and catalog pins before switching the active pointer; failure preserves the old immutable snapshot as stale evidence. Dispatch pins the selected schema/type-graph/view and checks freshness again at admission. The reference `ViewStore` is a single-thread state-machine oracle for this contract; a runtime requires a real transaction/lock and integration tests. View retention, quota and garbage collection follow the bounded derived-view policy in the design. No app monitoring scheduler is added.

Storage additionally rejects deletion of `active_registry` and `catalog_view` singletons and malformed lowercase SHA-256 values in imported binding IDs, source digests, registry-entry hashes and nullable overlay base hashes. `overlay_etags` is the executable cat1 projection for all overlay states, including tombstones and conflicts; its base component is the currently selected imported hash or `local` when the new selected base is absent. The old immutable base hash remains separate conflict evidence.


## Producer-to-inventory projection and executable device storage

`catalog_projection.py` enriches only derived registry entries; immutable binding_declarations and source bytes remain unchanged. `registry_inventory` contains one validated InventoryEntity per registry entry, sealed with the registry. Its variants use `dispatch_manifest.contract_digest`, contract format3, shared by generated aliases and generic dispatch schema pins. Source locators and permission metadata never establish a codec. Semantic type references and declared structured-type shapes contribute to the contract; changing this digest version requires explicit schema/grant reconciliation and does not silently retarget existing grants.

The SDK index producer now emits every historical, current, future and unknown-lifecycle record. `excluded_history_or_future` is retained only as a compatibility diagnostic for the native current-target projection; it no longer means records were omitted. Only `lifecycle_status=current-at-target` enters current exact-index annotation/JVM-equivalence lookup. This flag describes the frozen native SDK target, never a device extension observation or runtime authority. Raw member and container lifecycle attributes remain separate. Parsed `sdks` pairs use SDK ID0 for platform versions and declared nonzero SDK IDs for extension minima. Omitted member `sdks` inherits the container value because the public Metalava writer suppresses identical attributes; explicit member pairs replace that set. The containing type dependency enforces its independent lifetime. Unknown SDK IDs/syntax remain unknown with raw evidence. [Metalava source](https://android.googlesource.com/platform/tools/metalava/+/a9d285ca63f95134ff1eb2c02eff5638109a5ad3%5E2..a9d285ca63f95134ff1eb2c02eff5638109a5ad3/) documents the pair format and inheritance.

An index supplies introduced-inclusive/removed-exclusive ranges and separately evidenced extension alternatives. A source occurrence without an index proves only its explicit major.minor point, represented by `platform_point:[major,minor]`. A point match is available evidence; every other major/minor (including an unknown minor) is unknown with PLATFORM_APPLICABILITY_UNPROVEN. A point never fabricates a removal bound. An API major alone never proves a minor or a whole-major range. Metadata remains unknown when no source-supported rule exists. Reference fields resolve only a unique declared type in the same repository/revision/platform snapshot with package/nesting/import evidence. Intrinsic primitive/array leaves are explicit TypeReference.status=primitive and remain codec-unknown. Generic, wildcard, absent or ambiguous schemas remain unknown. Required unresolved type evidence is an AND-unknown predicate, so a proven version exclusion still yields unavailable. Containing types, argument/return types and structured-field schemas are dependencies; each pins the exact type contract hash. Full source/shape/evidence variants remain visible.

The builder streams `device_inventory.jsonl` and its versioned manifest, validates each InventoryEntity, enforces one-to-one entry counts, and includes the inventory metadata in the derived entry document hash. Older releases/copy migrations without this projection cannot supply a complete startup inventory; startup must reject an absent/incomplete inventory rather than inventing it. The inventory contract is DeviceResolution2.1.0: the additive platform_point key changes applicability semantics and requires explicit version handling. Resolved snapshots/Facts use DeviceView3.0.0: base contract_hash and transitive graph_digest produce the final schema_hash used by client grants. Earlier resolved drafts cannot activate silently. Previous draft snapshots remain historical evidence and are rejected for activation; no silent migration is defined. Existing Entry1.1 and catalog storage1.2 envelopes are unchanged. OpenAPI specification version is1.4.0.

`bridge-config.sql` now stores scoped epoch-bound capability facts, immutable staged/sealed device_views and device_view_entries, an active pointer with exact generation/epoch/catalog/overlay CAS, and append-only invalidation reasons. A catalog-pinned inventory_sha256 (canonical sorted InventoryEntity JSONL digest) and expected_inventory_count prevent partial or substituted inventories from activating. The trusted loader validates the complete inventory before sealing device_inventory_sets/members. Activation recomputes resolution from that pinned inventory/facts and rejects substituted members, contract hashes, dependencies or states. SQLite independently checks sealed inventory membership, selected base contracts and dependency pins; core SQLite has no built-in SHA256, so the offline loader verifies content hashes before sealing. `device_view_storage.py` is the offline SQLite transaction reference: validate the snapshot/facts/hash/type closure, write all rows, seal membership, then compare-and-switch inside BEGIN IMMEDIATE. Facts carry capability_epoch and observed_at; the resolver and publisher both reject old-epoch facts. Per-row graph_digest hashes the sorted transitive root/type `(entry_id,contract_hash)` closure and is rechecked at publication. `binding_availability` is a read-only fresh-active-view projection; `resolved_device_catalog` includes bindings and types. Neither grants permission. Wire mapping proof is versioned in binding_wire_contracts, separately from existence; unknown codecs/contracts cannot be invoked. Retention requires explicit maintenance and rejects active/pinned view deletion. No Android collector, Binder service, MCP service or HTTP deployment is implemented.

Resolved3 schema identity is SHA256(canonical `{schema_format:"closure3",contract_hash:C,graph_digest:G}`); G hashes the sorted transitive entry/base-contract pairs, including the root. This makes a dependent type change invalidate previous binding schema grants without cyclic hash recursion. Raw lifecycle/annotation headers stay in provenance and are excluded from semantic type shape hashes. Formal type variables never resolve to similarly named package/java.lang classes.

Strong status ETag syntax is `"dv2:<scope_sha256>:<generation>:<capability_epoch>:<catalog_generation>:<overlay_generation>:<inventory_sha256>"`; an uninitialized fixture store uses SHA256(canonical null) as the inventory token and cannot publish until it has a trusted inventory. All counters are canonical decimal. Inaccessible historical view/header and entry-list requests both return404 after authentication. Internal Device schemas are marked x-internal and are not request payloads.

A verified wire row must provide object codecs with nonempty codec_id and matching final schema_hash, plus nonempty evidence. The tuple (binding,schema,descriptor,transaction_code,nullable-interface-version) is unique; transaction codes/flags are uint32. These structural checks do not verify codec implementation or confer invocation authority: only a trusted adapter with complete proven ABI/layout may admit the row. Unknown/unsupported proof states remain visible.

Semantic contract format3 normalizes structured field/supertype references without their proof prose/source revision metadata, retains type parameters and declared supertypes, and includes parameter directions, known wire type annotations, oneway metadata and HIDL result types. Permission/lifecycle provenance remains separate. All hashes are versioned inputs to closure3; format2 grants/codecs are never silently migrated to new schema hashes. Unknown type/import/compiler/ABI semantics still prevent typed invocation.

The runtime input is effective_device_inventory.capture, taken under one read transaction and exact registry/catalog/overlay generation pins. It preserves every base, local, suppressed/conflict/deleted node. catalog_state/catalog_revision are independent of three-state version existence and per-client permission. Local additions lack positive applicability unless supported by imported evidence; no version is invented. Structured field overrides update their enclosing type and transitive schema hashes. Effective catalog_document_sha256 pins the canonical selected Entry metadata (independent of semantic schema hash); generated aliases reject stale documents and the offline known-route policy gate composes availability, whole-graph catalog exposure, current document pins and canonical client/OS authority decisions. The capture digest is over the effective inventory, including local state/revisions/document pins; the immutable producer manifest remains the base inventory digest. Global catalog edits invalidate views even when a metadata edit leaves the semantic schema hash stable.

The materializing Python oracle is an offline validation implementation, not the Android memory architecture. The exact historical008-scale checkpoint is retained with code hashes:799527entities,565.6seconds full resolution/validation,4.30GiB whole-probe peak. Later contract3/overlay changes are not retroactively measured. Runtime resolution stages complete results in indexed SQLite, uses available-edge/reverse indexes and bounded worklists/closure traversal, streams canonical hashes with bounded scratch storage, and activates only after complete checks. No Android performance or full799527-row SQLite activation is claimed.

Wire tuple identity is immutable/unique; evidence acquisition is separately append-only. wire_proof_revisions records complete versioned proof/codecs under the existing tuple, wire_proof_active selects a revision with next-revision CAS, and current_wire_proofs exposes either the selected revision or the immutable initial proof as revision0. Unknown proof can become verified, be superseded or be revoked to unknown/unsupported without rewriting history, changing semantic client schema grants or inventing a different tuple. Verified revisions require matching schema codecs and nonempty evidence. Admission/Ask pins the selected proof record_sha256 and revision, then rechecks selection immediately before dispatch; a changed/revoked proof invalidates that pending plan. This structural fixture does not verify an actual ABI: the trusted adapter must still verify endpoint/profile/device/interface/OEM compatibility and full codec implementation before invocation. No HTTP/MCP proof-write endpoint or Android operation is implemented.
