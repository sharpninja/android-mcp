`★ Insight ─────────────────────────────────────`
- In Structurizr DSL, every step in a `dynamic` view must reuse a relationship that already exists in the model, so a dynamic view can never introduce a dependency the component model lacks. That is why the missing `transport -> callbacks` edge (WS-01) surfaces as a mislabeled reverse edge: the author had no forward relationship to draw the read step on.
- Relationship descriptions in C4 are contracts, not decoration. Phrases like "Owns transactional writes" (WS-06) or "through local service" (WS-03) assert ownership and routing, and a hostile reader checks them against the actual edges. Keeping descriptions to what the edge truly carries avoids these contradictions.
- Image views are the only Structurizr mechanism for class-level detail, but the PlantUML exporter ignores them. If the Gradle pipeline exports through PlantUML, those five SVGs reach the Markdown only via explicit links, which is worth confirming in the build pass.
