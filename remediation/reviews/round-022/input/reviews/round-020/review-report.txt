## Remaining and new root causes

**N-01, medium, contradiction: legacy backend labels.** Line 658 sets the connection profile CHECK domain to native, self_adb and arc_target, and line 660 sets the executor domain to native, adb and arc_target. Lines 662-663 then say a stored external_adb row is rejected at admission, and lines 670-674 say stored avalonia_runtime and avalonia names remain compatibility labels pending a future versioned rename. Line 1640 says those rows are migrated explicitly to arc_target. A CHECK that excludes a value cannot store it for admission-time rejection, and a value cannot be both retained and migrated. Two implementers would ship different schemas. Minimal fix: delete the compatibility-label sentence at lines 670-674 and state that migration rewrites external_adb into host_forward_profiles and avalonia_runtime into arc_target before the live CHECK applies.

**N-02, low-medium, unspecified: outcome_unknown has no exits.** The table at lines 1581-1587 enters outcome_unknown on registration timeout but has no row for a late confirmed result, a delivered event, or callback.cancel from that state. The cancel contract at line 1341 forbids blind replay but does not say whether the retained provisional cleanup pins may be executed. Minimal fix: add three rows. A late result moves to active or closed. A delivered event is suppressed and journaled as a gap. Cancel moves to cancelling using the provisional pins.

**N-03, low-medium, unspecified: log inspection and export have no owner.** AuditLogger in workspace.dsl has only inbound edges, and its class exposes only record methods. Neither facade has an edge to AuditLogger or the database. Manifest controls SCR06.C01 and SCR06.C02 and STB05 steps 3 and 4 inspect and export logs, and line 1353 names sensitive export as a protected transition. Minimal fix: add a read and export operation on AuditLogger, an ownerCommands→audit relationship, and a redaction statement for export.

**N-04, low-medium, contradiction: resumable import stage.** Lines 836-837 say expiry or a closed admin window retains only an explicitly resumable stage. Line 1624 says expiry at the window end deletes unactivated staging. Nothing defines how a stage becomes resumable, its lifetime, or the proof needed to resume. Minimal fix: remove the resumable clause, or define a resumable flag with a bounded lifetime and fresh owner proof on resume.

**N-06, low, inconsistency: start and stop protection level.** The ownerCommands→lifecycle edge in workspace.dsl reads "requests protected desired state". Line 1353 does not list desired-state changes among protected transitions, and line 295 lets the unprotected notification Stop action change desired state. Minimal fix: route start and stop through SessionCommandFacade as an ordinary command and relabel the edge.

**N-07, low-medium, unspecified: ARC authentication source.** The code view defines ArcAuthenticator separately from ClientAuthenticator. The ArcComponents view excludes the auth component, and no arc→auth or arc→db relationship exists. Requirement 2 places client mapping in SQLite and requirement 5 forbids a second authority. Minimal fix: declare ArcAuthenticator as an adapter over ClientAuthenticator and add the relationship.

**F-04 residual, low: stale screen table.** No delta operation touches the S9 screen table; the nearest operations are at lines 288, 295 and 374. That table therefore cannot list SCR11, STB04 or STB05 added this round, which contradicts line 1273. Minimal fix: regenerate the table from the manifest.

**Low residual bundle.** The ui-screens-and-storyboards.md sections repeat SCR02 and SCR07 boilerplate under every screen. The crosswalk names a "router" class that does not exist in the arc-ui view. The spike sentence at line 1363 says "client certificate pinning" where it means the client pins the server certificate. The isError choice at line 1630 is defensible only under the tools page's "invalid input data" wording; the same page lists "invalid arguments" as a protocol error, so the split must be confirmed against the pinned text rather than asserted.

`★ Insight ─────────────────────────────────────`
A CHECK constraint is a statement about what rows can exist, so prose that describes admission-time handling of excluded values is unimplementable rather than merely redundant. Schema domains, migrations and reason codes have to be stated as one ordered story.
A state machine is only closed when every non-terminal state has an exit for every event that can still arrive; late Binder results after a timeout are the classic missed row.
