# Snapshot caller proposal for Root and Publication

Sources/Snapshot uses the same native application and category target. Required parameters: `project-root`, `source-manifest`, `recipe-lock`, `output-root`. Optional: `generation`, `release`, `snapshot-mode` (`Fetch` or `Restore`, default `Restore`), `download` (default false), `bundle-root` (required only when selected missing inputs require bundled snapshots). The source manifest is a checksum-locked recipe; the old Python path is retained as evidence and is never executed.

Publication must expose exact typed per-logical-row status, status-field presence, SourcePin and immutable-snapshot/prerequisite metadata from its sole existing parse loop. The proposed additive interface is in `RehydrationSnapshotContracts.cs.proposed`. A missing status field preserves the original caller error; explicit null/nonstring status is not downloaded. This preserves current Plan and PlanSeed output bytes and first/last alias semantics. The new service must not parse OriginalRow or reuse the physical winner as a substitute for the exact logical row.

Select `Status == downloaded`, first logical row for each Git blob, preserving original order. Unknown/missing Git addresses cannot silently group together in native acquisition. Existing output targets are only read. Restore verifies SHA256/Git/size before reporting missing counts; Fetch preserves the original behavior of counting by existence without re-verifying an existing file. Default dry-run writes no raw files or receipts and calls no transport. Original Fetch dry-run exits 1 even with zero missing; Restore dry-run exits 0. Report these via the returned ExitCode and let Root's Build host apply the code after JSON output.

Only explicit download delegates selected missing typed pins to the shared SourceBatch, shared SourceAcquirer and original compatibility profile. No extra URL/parser/storage implementation is introduced. Preflight all existing Restore inputs and selected bundle prerequisites before any transfer. Per-member verification, refusal of mutable fallback, exact range/version checks and immutable batch seals remain the shared engines' responsibility. Download completion reports missing-before, downloaded and retained-existing counts separately from whole-corpus completeness. A source failure leaves originals and omits the final batch seal.

Root owns Build.SourcesSnapshot.cs, registry/enum/parameter admission, CLI composition and output-directory boundaries. Acquisition owns the service and SAME-case mock/native tests. Publication helper owns the documented `tools/rehydrate.ps1`; this proposal does not edit its checkout. Legacy recipe producer sources remain retained until Root reconciles all obligations.
