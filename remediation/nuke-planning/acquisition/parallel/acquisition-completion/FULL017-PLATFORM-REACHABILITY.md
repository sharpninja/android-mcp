Exact original paths/hashes and canonical native source pins are in `published014-full017-reconciliation-proposal.json`. ## Actually reachable gap

The row must be in a valid checksum-locked recipe, have valid source/archive URLs, paths, hash/Git/size pins and bounded-sdk-zip-range-member transport, be downloaded and the first winning Git row, have a missing raw target, and be explicitly downloaded under CanonicalRestore/Restore. Otherwise this reference either does not activate or the established native admission may reject an earlier requirement. Default dry-run, exact reuse and explicit Generic bypass proof loading and must continue to do so.

When row.platform_api_version is absent/null/empty, any nonstring transport.platform_api_version is accepted as ignored JSON by current PlanCore. A truthy numeric/bool/container value is then lost because the seven-field Snapshot reference retains only strings. It becomes null and the proof reader returns SDK_PLATFORM after receipt admission and before XML. The original can continue with that truthy value and select an exact XML package. This is a genuine production-reachable projection difference on custom valid recipes, not merely absent test evidence. The inspected frozen release011 metadata rows use row string37.2, so this analysis does not claim that the six actual frozen rows hit the gap.

There is an additional admitted row domain. SourceArchivePin uses `OptionalText(transport,"platform_version") ?? OptionalText(row,"platform_api_version")`. A nonnull string in native transport.platform_version short-circuits the row OptionalText call. No later row-context field reads platform_api_version as a string. Therefore nonstring row values can reach captureSnapshot in this branch. The capture accepts only row strings and permits transport fallback only for row Undefined/Null/String, so it loses both truthy nonstring row precedence and false nonstring row fallback. Without a nonnull native platform_version, a nonstring row normally rejects earlier through OptionalText; that branch should not be broadened inadvertently. The earlier proposal's broad statement that native always rejects nonstring rows was incomplete; this source audit supplies the missing short-circuit qualification.

False/null/zero/empty transport fallback values already lead to missing-platform refusal in both source flows, after receipt handling. Nonempty row strings override transport regardless of transport type. Whitespace row strings are truthy in the original; the existing native SDK validator rejects blank/whitespace platforms as an explicit stronger admission rule. Preserve that strict validator rather than weakening it to claim parity.

## Minimal proposed caller cases

Use the already proven MetadataCaller/MetadataProof fixtures and the same sole planner/binder/batch seams. Keep all ordinary lock, source, receipt/XML and range pins valid. Derive expected outcomes from the pinned original and retain independent negative controls before a producer edit.

- Missing row platform, legacy transport numeric37.2, package absent, XML package platforms;android-37.2: original reaches the exact package/range path; current reference loses the value and fails SDK_PLATFORM. This is the smallest positive numeric counterexample.
- Missing row platform, legacy transport false or0: both refuse SDK_PLATFORM after receipt and before XML, with no network/output/seal. This protects refusal order without adding a formatter.
- Nonempty row string37.2, legacy transport numeric or object: row string wins and existing admitted behavior stays unchanged.
- Row false, native transport.platform_version string99.0, legacy transport.platform_api_version string37.2: the row is admitted by the native short-circuit; original falls back to37.2, while current capture does not. This case requires correct truth/fallback projection, not a numeric/container formatter.
- Row numeric37.2, native transport.platform_version string99.0, legacy transport string36.0: original row value wins. Current capture loses it. Preserve this already admitted domain without broadening the earlier no-native-platform branch.
- Repeat a numeric-gap recipe as default dry-run and exact-target reuse, with a missing/invalid proof envelope: preserve zero envelope/sidecar reads and zero effects.
- Retain wrong XML package, missing/ambiguous package, size disagreement and whitespace platform refusals after any projection evolution. Do not relax the existing SDK validator.

Truthy booleans and nonempty arrays/objects require Python-compatible str/repr semantics if that broader original domain is claimed. Raw JSON text is not equivalent. The minimal sole-helper projection may carry a detached typed selected legacy value/presence/kind fact only for the currently unrepresentable cases, omitting it for existing string-domain wires. Selection must cover both row and transport facts, including the short-circuit-admitted row values. The acquisition consumer must use an agreed shared compatibility formatter if one exists; no OriginalRow parse or parallel scalar/container engine is authorized by this read-only proposal.

## Separate original HTTP boundary

Original restore get calls urlopen with timeout60, and original fetch module uses timeout45. Full017 PinnedRequest has no explicit timeout field, HttpByteTransport.Create does not configure either original duration, and SnapshotFetchTransport changes only Retry. This establishes that the original timeout settings are not represented in the current request/policy composition. It does not assert a measured runtime timeout or network failure mode; no live network or timeout experiment was run. Keep this original-method boundary explicit rather than treating retry/body/range tests as proof of it.
