# Sole helper proposal: broader legacy transport platform values

Proposal only. No Publication PlanCore, reader formatting or original-row parser is changed by this note.

The original current and frozen restore_metadata obtains `s.get('platform_api_version') or t.get('platform_api_version')`, then rejects a false value, and constructs the absent package default with Python `str(platform)`. Original source paths, hashes and exact function anchors remain pinned by the owner baseline. The typed native producer already rejects nonstring row.platform_api_version and archive package_path; preserving those established admission rules is separate from the currently unrepresented transport.platform_api_version domain.

For a missing/null/empty row string, transport values may be null, bool, integer, float, string, array or object under JSON. False/null/numeric zero/empty string/empty array/empty object are false; true/nonzero/nonempty containers are true. A truthy transport value can therefore affect the package string, not just whether a prerequisite is missing. Do not stringify a raw JSON token as though it were Python str: True uses capitals, integer formatting can be arbitrary precision, float decimal/exponent/signed-zero rendering differs, and list/dict str uses recursive Python repr (including string escaping, None and boolean spellings). Whitespace strings are truthy in Python, while the existing native SDK validator's whitespace-platform refusal is an explicitly stronger native admission rule.

Minimal additive projection suggestion for the sole helper: append an optional typed `LegacyPlatformValue` fact to RehydrationCanonicalMetadataReference, populated only when the selected legacy transport.platform_api_version is present and nonstring. The fact carries JsonValueKind plus a detached cloned JsonElement value. Existing nullable PlatformVersion and seven-field string-domain behavior remain unchanged; omit the new fact when null so prior string-domain projection wires and expected values remain stable. Presence/kind must distinguish explicit JSON null from absence. Capture it in the existing sole PlanCore walk; never let Acquisition read OriginalRow or reconstruct the selection from serialized rows.

Before activation, the sole helper should extend its mock/native cases for transport null/false/true,0/-0.0/nonzero integer/large integer/float,empty/nonempty arrays and objects, and precedence from existing row strings. Do not broaden Plan/PlanSeed admission as a side effect. The acquisition side must use one agreed shared JSON truth/formatting authority, preferably an existing Root-owned compatibility utility if one exists; it must not introduce its own second scalar/float/container formatter. XML package/size validation stays in SdkArchiveVersionValidator. Any unsupported or deliberately stricter domain remains explicit instead of being called whole original restore_metadata parity.

This proposal does not block the admitted string-domain Sources/Snapshot CLI completion. It is a separate remaining original-producer responsibility for Root and the sole Publication helper.
