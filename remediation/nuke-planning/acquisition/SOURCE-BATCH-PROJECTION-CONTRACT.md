# SourceBatch projection boundary

Parent owns CLI wiring. Publication owns the sole recipe parser and typed validated source-row projection. Acquisition will own `Modules/Sources/Acquisition/SourceBatchContracts.cs` and `SourceBatch.cs`, with identical-case fixtures under `Tests/Sources/Acquisition`.

Use the existing `SourcePin`, `SourceArchivePin`, `HistoricalCachePin` and `SnapshotRequirement` models. Publication's authoritative `RehydrationSourceProjection` in `Modules/Publication/RehydrationSourceProjectionContracts.cs` retains every logical row even when source bytes/local paths deduplicate, original row order, source kind/context/provenance, required immutable snapshot identity and optional bundle path, cache count/producer/source/recipe pins, and archive prerequisites. The batch must not parse recipe or plan-manifest JSON to recover omitted fields. `SourceBatchRequest` consumes that exact type; no duplicate row model is introduced here.

Compatibility defaults explicitly to `CanonicalRestore`. `GenericRehydrate` is accepted only when explicitly selected in the request, never inferred from release, missing container hashes, source kind or missing prerequisites. `SourcePin.Compatibility` and nested `SourceArchivePin.Compatibility` must match the selected profile; contradictions fail before effects.

Canonical network acquisition of metadata ranges requires original ETag, explicit platform version and repository XML proving the exact package/archive size. Six known metadata rows lack these prerequisites. Missing raw bytes for those rows cannot be restored canonically. Explicit generic mode may request only bounded allowlisted metadata with mandatory member SHA; it must retain unknown whole-container identity and must never claim canonical ETag/package proof.

The existing source acquirer first verifies any already-present target against SHA256, optional exact size and Git blob. A matching target may be reused without upstream access or new archive proof; unproven container evidence remains unknown. Existing mismatches always fail and retain originals. Prerequisites apply to work that needs acquisition, not to a fresh assertion that a verified cached member proves an entire container.

An immutable required snapshot is a typed requirement even when its bundle path is missing. It must not disappear into a null `RequiredLocalSnapshot` that causes HTTP fallback. If the selected target is absent, the declared snapshot and every other selected prerequisite must be available and verified before any batch network/output writes. Bundle import copies/verifies while retaining its original.

Batch receipts must bind one recipe/profile/selection per generation, retain all aliases/context, report full/selected/processed denominators, preserve partial/unknown evidence, and seal only after all recorded outputs verify. The caller owns physical output-root admission/freshness and final category dispatch. No registry or recipe parser is duplicated here.

`SourceBatchCachePolicy.PreserveAliases` acquires raw source bytes and retains all cache alias evidence without claiming those caches exist. `ImportLockedHistorical` additionally validates selected historical cache pins using `HistoricalSourceCache`, copies the exact pinned gzip from the bundle store, and retains its original producer fingerprint. Missing legacy kind/count remains a prerequisite; neither zero records nor a C# identity is invented. SourceBatch raw completeness is the selected physical sources divided by the entire projected physical inventory; it does not claim extractor, database, catalog validation, historical gzip regeneration, or final category dispatch completeness.

The bundle and output stores are separate explicit `IArtifactStore` dependencies. All selected source target hashes, snapshot bytes, historical cache imports, projection associations and typed prerequisites are preflighted before the first output write or HTTP request. Matching existing source bytes avoid upstream requirements; conflicting bytes stop and remain intact. A sealed receipt is checked against the full canonical request identity and every recorded artifact; a missing sealed artifact fails instead of rebuilding underneath the receipt. Interrupted unsealed output can resume only by exact content identity. Receipt serialization is canonical and its immutable write is last.

Native API: `new SourceBatch(transport, outputStore, bundleStore, leases, canonical).RunAsync(new SourceBatchRequest(generationId, receiptPath, projection, cachePolicy), cancellationToken)`. `SourceBatchResult.Receipt.Sources` retains physical indices and acquired artifact identities; `Receipt.Projection.Rows` retains all logical associations and context for the caller's category dispatch. No process runner is used and no source or wrapper is executed. The sole shared source-pin validator is exposed internally for batch preflight; its validation algorithm is unchanged.
