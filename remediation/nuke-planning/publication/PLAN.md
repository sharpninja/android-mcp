# Native publication and rehydration component

Approved ownership: `Modules/Publication`, `Tests/Publication`, and this planning directory only. The root owns shared contracts, dispatch, project files and the test scheduler. There are no Git operations, automatic pushes, provider calls, Python, custom Node, or GitHub Actions in this component.

## BDPv4 increments and acceptance mapping

1. PUB-01 through PUB-17: read-only allowlist checks. Correct scripted results and individual wrong counts, bytes, codes, paths and omissions must pass the mock gate before the checker is implemented. The real provider runs those exact cases. Tracked snapshots are supplied by the caller; symlink/regular-file observations must be trustworthy. The artifact store independently rejects unsafe filesystem traversal.
2. STAGE: pin every source, reject duplicate/unsafe destinations and forbidden deliverables, preflight every source and existing destination before the first write. Shared `IArtifactLeaseProvider` serializes cooperating writers. Shared `IArtifactStore` writes new-or-identical atomically, preserves conflicts and partial failures. Copy under `generations/{id}/files/`; reverify source/destination pins, then write `generations/{id}/manifest.json` last. No manifest means uncommitted. Same inputs/generation resume idempotently; no deletes, source mutation or relabeling. No cross-process safety claim against malicious external mutation; detect changes at commit verification. Preserve partial outputs on cancel/crash and report failure truthfully.
3. REHYDRATE: validate recipe raw SHA256 against its lock, version/release, every source/cache/producer relative path and SHA pin, source-size consistency and conflicting aliases before emitting a pure canonical manifest. Preserve row count versus unique path count, known versus unknown bytes, mutable-upstream owner-supplied snapshot requirements, original expected/provenance/limits/environment evidence and historical limitations. No source acquisition/extraction is duplicated: emit references to shared category/operation keys. Help reads authoritative operation definitions; it must not advertise unimplemented adapters as working.

Dependencies: shared `ICanonicalJson`, injected `IContentHash` or hash delegate, `IArtifactStore`, `IArtifactLeaseProvider`, `IClock`. `IProcessRunner` remains unused because these services do not start processes. Root integrates typed CLI/registry parameters: Publish Check (git-checkout), Publish Stage (git-checkout, deliverable-manifest, output-root; optional source-root), Catalog Rehydrate (recipe, output-root; optional cache-root/resume). Stage means a copied bundle, not a Git index operation.

No production implementation is authorized by a mock test count alone. Each increment retains its mock receipt first, then adds the real binding and real receipt. HV is deferred until the PR is ready; normal local verification precedes ready-for-review. No acceptance or full legacy-parity claim is made by this plan.
