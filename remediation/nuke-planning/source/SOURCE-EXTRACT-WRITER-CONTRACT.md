# Cache-only Source writer increment

This increment follows the native reader/resolver45, archive11, binary12 and factory8 gates. Tests and scripted fakes must pass before the writer is added to the same `SourcesExtractService`. The actual Extract operation and CLI remain pending.

The service gains the existing `ISourcesExtractOperation` interface and an optional sixth constructor dependency, `IArtifactLeaseProvider`. Existing reader/resolver callers remain unchanged; Extract requires that dependency before effects. The writer reuses its own admitted disposable generation and runtime, the same raw resolver, the same descriptor-derived cache capabilities, and the same sealed lookup memo. It adds no source-kind or recipe parser.

Selection follows logical projection row order, choosing kinds declared cache-capable by the actual runtime. `CacheSourceLimit` counts those logical rows, including aliases; negative limits fail preflight, zero selects none. Acquisition's physical-source limit is not applied again. No prior index means fresh raw extraction. A caller-pinned prior index uses the already-proved reader admission. Each hit skips raw reads, parser execution and facade declaration-payload parsing.

Distinct source-document identities retain separate metadata/context. Alias groups may reuse publication only if source/kind/producer identity and canonical declaration-array bytes agree. Conflicts fail before any generation commit. Matching prior-hit seals can be reused without republishing or decoding declarations. Fresh alias groups publish once through the existing `ISealedSourceCache.PublishAsync` engine. Returned rows retain per-logical-row metadata, issues, context, raw diagnostic evidence and hit/miss disposition.

The Core `ArtifactGenerationRuntime` remains the only immutable generation protocol. Source prepares a read-only, explicitly bound input view over raw source and generation stores. Input names are qualified by `source/` or `generation/`; this distinguishes the stores without changing source-row identity. Raw misses, admitted prior commit/index data and reused gzip/sidecars are pinned Core inputs, so Core rechecks exact bytes before final commit without a second sealed lookup or payload parse.

The Core output plan includes the domain index-data file and every new cache data/sidecar path. Freshness is checked before materialization. The cache SPI creates ancillary immutable blobs during materialization; Core then reads/verifies those exact artifacts through the same output store and commits the typed Source generation manifest last. Failed partial artifacts remain retained and uncommitted. The manifest owns all newly written artifacts and references the domain index-data pin; reused historical native seals remain explicit index references. Python cache identities are never relabeled.

Required mock scenarios cover raw publication, trusted missing-raw hit, alias row limit and alias publication count, zero/negative limits, dynamic registered cache capability, unknown platform preservation, issue/raw retention, alias payload conflict, output occupancy, source/index pins, cancellation, dependency failure, immutable input retention, commit-last ordering and suppressed parser/raw access on a hit. The same cases and interaction assertions will bind to the native writer. A subsequent actual registered Sources/Extract CLI and Catalog consumer run must prove the full caller path; standalone service tests cannot establish that completion.
