## Failure and test discrimination

- Explicit context missing, blank, malformed, or unsupported numeric form must reject before any dependency effect. Lock the exact accepted major/minor domain against source `sdk_api_index.py:version`, including existing historical behavior, before production; do not silently fix broad legacy version acceptance without a requirement decision.
- Unsupported XML root or version, truncated XML, duplicate attribute, illegal encoding, external DTD/entity and entity expansion fixtures reject through the locked error seam. Verify zero network/tool/file mutation via scripted boundaries and original source hash.
- Every valid record property receives an individually wrong or omitted mock. Generic controls also drop/duplicate/reorder records, promote noncurrent/unknown state, invent field/type/permission metadata, erase raw attributes, change physical line/ordinal, change source/context, and suppress an issue.
- Invalid descriptor fixtures must prove both unsupported-row preservation and continued following-row extraction. Malformed whole XML must not masquerade as a clean empty result.
- Mock gate requires all discovered cases/control variants passed, Failed0, Skipped0, immutable TRX and source/fixture hashes. Parent acknowledgement then unlocks only this production slice. No new expected values may be extracted from the real parser.

## Proposed implementation after the green mock gate

One source-owned XML reader uses .NET XmlReader with prohibited DTD processing, no external resolver and `IXmlLineInfo` for physical locations. It reads pinned source bytes, preserves literal attribute dictionaries/owner context and performs exact JVM descriptor parsing with explicit source-type unknowns. Domain version comparison must use an approved shared platform-version contract or remain a private source-domain implementation until root identifies other consumers; do not create competing Catalog/SDK comparers. Producer/cache identity and any canonical document hashing use root-approved `ICanonicalJson` and ContentHash, not JsonNode's ordinary serialization. No network/acquisition is introduced by the XML adapter.
