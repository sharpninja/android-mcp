# Source-owned native cache intake

This records the approved006 contract and current implementation boundary. It does not claim the pending native gate or Catalog consumer has passed.

`Modules/Sources/SourceExtractContracts.cs` is the single typed authority. JSON is the default .NET serialization of those records, inspected and canonicalized by shared `ICanonicalJson`. There is no parallel Catalog recipe, index or cache codec.

The caller supplies an explicit `StoredArtifact` pin for the committed generation manifest. The Source reader checks its SHA256 and length before JSON inspection, then checks its pinned index-data artifact before inspecting that data. A mutable index's freshly computed hash is never its admission authority.

The committed manifest schema is `androidmcp-native-source-generation-v1`. It contains `GenerationId`, immutable input/output artifact pins, and `IndexData`, which must be one of its outputs. The Source index-data schema is `androidmcp-native-source-index-v1`. It retains release, recipe SHA256, extraction profile, explicit native producer/code/runtime/parser/context identity, and cached logical rows. The planned writer uses the existing Core `ArtifactGenerationRuntime` for commit-last behavior. Ancillary immutable cache files do not establish a committed generation on their own.

Each indexed row retains the existing projection's row index, logical path, declared kind, physical index and cache alias index; source SHA256 and admitted byte length; shared-canonical hash of the exact `OriginalRow`; source context and scope; structural status, original issues, metadata; required lossless raw evidence; and the exact native cache receipt/data/sidecar/count seal. The existing `RehydrationSourceProjection` remains the only recipe-to-row parser.

Source context uses repository and revision from the admitted row, with the physical pinned revision as fallback, and the recipe SHA256 as snapshot identity. Explicit original `platform_api_version` is preserved as text or null. Acquisition release context cannot establish Android applicability. Catalog's SQL `source_id` remains a separate value and cannot rewrite this context or the producer metadata.

`SourcesExtractService(rawSources, generations, runtimes, cache, canonical)` currently implements `ISourceExtractGenerationReader` and `ISourceExtractResolver`. `OpenAsync` admits a supplied generation or opens explicit raw-only intake. Its disposable generation owns the runtime through all row reads. Cache capabilities derive from the actual runtime registrations through `ISourcesCacheRuntime`; the pending factory descriptor increment exposes those flags. Upfront optional Java native admission and ABI checks are allowed on a hit. A hit skips raw reads, `Dispatcher.Extract`, `WithTree`, and declaration-payload parsing in this facade.

`ReadAsync(existingRow)` uses the sole `ISealedSourceCache.LookupAsync` for admitted indexed rows. Equivalent exact cache identities share a lookup; each logical row retains its own sealed metadata/context. Records remain canonical declaration-array bytes at this boundary. Catalog may strictly deserialize those bytes once at its private-stage ingestion. It must not call another cache decoder or rerun raw extraction on a verified hit.

Unindexed and noncache rows resolve raw through the same Source service. `ResolveAsync` verifies raw SHA256, declared size and optional Git blob before calling the one dispatcher. The Source service emits no catalog SQL entries and writes no generation artifacts in this bounded reader/resolver increment. Catalog still performs required final raw-pin checks for raw-resolved rows; verified hits use their admitted immutable evidence instead.

Every row with issues, Unsupported status or Malformed status must retain complete valid base64 source bytes whose SHA256 and length match the source pin. Missing or invalid evidence fails admission. Clean rows may omit that whole-source copy. Catalog's issue reporting must consume the retained evidence on hits instead of rereading an absent raw file.

The separate pending `Sources/Extract` writer is cache-only, matching the legacy logical cache-row limit. Actual managed cache-capable providers are SDK API index and an explicitly admitted Java provider. Exact source-document identities may memoize extraction; different paths/context retain separate identities. Alias publication deduplicates only matching canonical payload and producer/seal identity, with conflicts preventing index commit. Historical Python gzip/cache identities remain verified-unused evidence, never native hits relabeled with new fingerprints.
