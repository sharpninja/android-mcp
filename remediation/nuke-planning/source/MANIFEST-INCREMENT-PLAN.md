This is the next mock-first slice of FR-BUILD-004/TEST-BUILD-004, S-AC019 and the definition/reference boundary of S-AC020. The published `tools/source_facts/manifest_source.py` and its six legacy test methods are fixture evidence read as text; they are never executed. The parser in `catalog/tooling/build_catalog.py` supplies the permission-definition storage behavior. Catalog owns storage/export; Sources supplies one pure parser.

The source-owned provider will implement `ISourceExtractor`, kind `manifest`. Records retain only literal permission/permission-tree/permission-group/uses-permission/uses-permission-sdk-23 facts, source line, Clark-name attributes and nested element evidence. A `permission` element with Android-namespace name is definition evidence. Uses-permission is reference evidence and cannot become a definition. Names lacking the Android namespace remain literal raw attributes, with an explicit missing-name issue. Protection level is retained as spelling without policy interpretation. Duplicate definition names within one source remain separate rows plus a duplicate issue, so Catalog can retain the original without silently selecting one. No OS/client grants or installed-state facts are emitted.

Metadata retains the normalization receipt. Empty bytes produce zero records and `empty-source-no-declarations`, permission_elements0, valid_android_manifestfalse. UTF8 BOM is decoded without modifying source bytes. Only leading whitespace/XML comments may precede a late XML1.0 declaration. An exactly supported UTF8 declaration is masked with equal code-point spaces while preserving line feeds; receipt contains original declaration, code-point span and raw_source_unchangedtrue. Noncomment content, late unsupported encoding/declaration shape, malformed XML, wrong root, binary Android XML and DTD/external entities fail with FormatException and never create invented records. Caller preconditions use ArgumentException. The outer operation retains source identity/hash/failure reason. A non-UTF8 XML declaration is read by the XML reader as declared, without claiming a UTF8 repair.
