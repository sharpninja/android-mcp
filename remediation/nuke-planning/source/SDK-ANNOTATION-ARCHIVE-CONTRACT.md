# SDK annotation archive source boundary

The source producer Kind is sdk-annotations and implements the explicit IBinarySourceExtractor marker. Dispatcher determines the registered provider before UTF8 text admission; only a marked registered provider receives binary bytes. File extensions never choose a route. Unknown binary kinds retain the existing lossless unsupported source identity behavior. UTF8 admission for every existing text provider stays unchanged.

SdkAnnotationsSourceExtractor returns no declaration records. Metadata.annotation_archive is the single owned concern JSON object. Its shape is:

- status: parsed or partial.
- members: archive member names in Unicode scalar sorted iteration order, retaining duplicate-name occurrences.
- items: one object per direct item element from each well formed XML member, retaining empty names and unmatched targets. Each item has archive_member, item_ordinal, item_name, scope, owner, target_canonical, java_lang_shortened_candidate, package_candidate, declared_type, declared_type_shortened, declared_type_java_lang_roots, parameter_java_lang_roots, is_constructor and annotations. declared_type is the literal normalized method return or field type; it is null for a constructor or owner/package target. The shortened type and root-name sets preserve the source-pinned annotation_link spelling rules. The legacy parameter root scan uses the canonical substring after the first opening parenthesis, or the entire canonical if there is none. Root arrays are deterministic Unicode scalar sorted unique names. package_candidate is exactly package: followed by the owner; Catalog supplies the language namespace. This prevents Catalog from copying XML return/field spelling, shortening or root-name regexes.
- annotations: nested objects with annotation_ordinal, name, arguments, raw and values. values retains each direct val element's literal attribute dictionary. arguments joins name=val in original val order. raw uses the existing sole SourceXmlFormatter.
- counts: xml_documents, items and annotations.
- issues: explicit member and parse facts. Non-XML members remain unrecognized-member issues. Malformed XML retains member identity plus raw bytes with explicit encoding; no invented item is emitted. A malformed ZIP fails extraction visibly with complete raw source identity at the outer dispatcher boundary.

Item scope is declaration or parameter:N from the literal trailing decimal ordinal. The pure Source target-spelling service removes only that suffix, separates the owner and spelling, and normalizes the legacy declaration canonical through shared SourceSyntax type/parameter helpers. The optional java.lang-shortened candidate is spelling evidence only. package_candidate applies only to owner/package-only targets. Raw item_name always remains available for SourceTypeFacts.XmlJvmKey with proven SDK owners.

Catalog owns platform-current lookup, exact descriptor proof through the shared JVM helper, same-snapshot sdk-signature eligibility using repository/revision/platform, annotation attachment and permission relation publication. The producer supplies no binding_id, target resolution authority, compiler validity or runtime grant. Existing IAnnotationTargetSourceFacts and scoped Catalog rules are not copied.

This contract is staged before production. The next gate first proves pure spelling, ZIP/XML evidence and explicit binary-dispatch mocks, including malformed/unknown members, lossless UTF8 refusal outside the binary route, and unchanged existing text fixtures. Only after root acknowledges those mocks can the producer/dispatcher/factory update be implemented and the same fixtures bound natively. Existing factory supported-kind expectations gain this registered kind through the same prior mock gate; the alias table remains solely in the dispatcher.
