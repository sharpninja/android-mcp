## One application and authoritative dispatch

Use one C# NUKE executable project with internal folders/namespaces, never one executable or target per former script. The parent owns the single typed category/operation registry. This slice contributes target category `Sources` and operations `Plan`, `Seed`, `Fetch`, `Inventory`, `Extract`, `Provenance`. The old Doctor capability is an internal call to the parent's canonical `Validate Toolchain` service/operation, never a second Sources operation. The registry defines each legal pair, typed options, input/output contracts, prerequisite checks, network permission, side effects, receipt schema, dispatch delegate, and tests. Help and documentation are projections of that registry. No second switch/list of legal operations may exist in adapters, help, tests, or docs.

Examples of intended CLI shape: `--target Sources --operation Plan --recipe <path>`; `--target Sources --operation Fetch --workspace <new generation> --recipe <path>`; `--target Sources --operation Extract --source-kind Aidl --profile Candidate --workspace <path>`; `--target Sources --operation Provenance --workspace <path>`. Exact NUKE option spelling must follow parent registry contract. Fetch covers both existing snapshot-restore entry paths through one acquisition engine; no separate Restore implementation. Build/validate/export catalog operations belong to the parent's Catalog category and call the same source services. Inventory is pinned selection and reconciliation only; it must not silently broaden source scope or contact new repositories.

`Plan` and canonical toolchain validation have no acquisition or generation side effects. `Seed` copies and verifies from an explicitly supplied bundle, retaining originals. `Fetch` acquires only pinned inputs. `Extract` produces new versioned declaration/evidence generations. `Provenance` emits a receipt over selected inputs, producer identity, selected profile, output hashes and limitations. Unknown categories, operations, source kinds, incompatible option combinations, and output paths fail before network/file mutation.

## Proposed internal C# seams

These are application interfaces proposed for tests; they are not claims about third-party APIs.

- `SourceOperationHandler.ExecuteAsync(SourceRequest, CancellationToken) -> SourceRunReceipt`. Sole registry handler, orchestrates shared services and status. `SourceRequest` includes profile, recipe, workspace, source-kind filter, optional nonnegative limit, explicit fixture transport allowance, strict cache-byte policy, and bundle path.
- `RecipeReader.Read(Stream, RecipeLock) -> SourceRecipe`. Validates recipe version, nonempty selection, every content pin and all contained paths before mutation. Keeps source identities and selection origins distinct even when bytes deduplicate.
- `WorkspacePathPolicy.Resolve(root, relative) -> SafePath`. One implementation for recipe, source, cache, archive, receipt and output paths; checks canonical components, existing symlinks and final containment. Source and publication roots are never writable outputs.
- `IByteTransport.ReadAsync(PinnedRequest) -> TransportResponse` and `IRangeSource.ReadAsync(offset, length, versionPin) -> bytes`. Scripted fakes record request method, URL, headers, byte ranges, retries and call order. No source content execution or subprocess escape.
- `SourceAcquirer.AcquireAsync(SourcePin, Workspace) -> AcquiredSource`. Reuse matching bytes without network; reject existing mismatches while preserving them. Verify SHA-256, optional Git blob `blob <decimal-byte-count> NUL <bytes>` SHA-1, size and declared archive/member pins before atomic publication.
- `MetadataArchiveReader.ReadSelectedAsync(ArchivePin, IRangeSource) -> ArchiveEvidence`. One bounded ZIP engine for pinned full source archives and metadata-only range profiles. It returns selected bytes and the whole central-directory entry inventory, including unselected entries, without reading binary payloads.
- `IDeclarationExtractor.Extract(ReadOnlyMemory<byte>, SourceContext) -> ExtractionBatch`. Shared record envelope carries canonical identity, kind, owner/package/name, type/parameter/annotation data, exact original raw text, source byte/character ranges and line, extras, issue records, parser identity, coverage limits. Each format is a pure internal adapter using shared lexical and provenance services.
- `SourceLinker.Link(batch, PinnedEvidenceIndex) -> LinkedBatch`. Explicit JVM identities, annotation targets, build/dump memberships and applicability only with the required source/snapshot proof. Never make a successful structural parse imply runtime authority, Binder codec support or OS availability.
- `CacheStore.Read/Write(SourcePin, ProducerProfile, batch) -> CacheReceipt`. Shared canonical JSON/hash/compression semantics. A C# producer gets a new producer/cache identity; it must never stamp a Python fingerprint on C# output. Original cache hash and new cache hash remain separate.
- `ProvenanceWriter.Write(SourceRun) -> SourceRunReceipt`. One canonical serializer/hash utility shared with parent catalog, document and registry services. Receipt says selected/unique/processed/remaining counts, fixture/real binding, full/partial coverage, exact input/output hashes, source/profile/parser pins, issues and all unknown limits.

## Acquisition, cache and resume contract

Legacy anchors: `tools/rehydrate.py:40` safe paths; `:76` locked recipe; `:97` existing-input checks; `:126` exact HTTP ranges; `:168` archive members; `:210` acquisition; `:258` recipe workspace binding; `:277` caches; `:357` stage sealing. Canonical `restore_snapshot.py:9` retries, `:22` bounded source archives, `:38` bundled snapshot, `:45` ETag-protected metadata. `sdk_zip_metadata.py:8` range stream, `:22` selected names, `:26` ZIP metadata.

Lock all inputs to one recipe digest per workspace generation before acquisition. A changed recipe requires a separate generation; a matching successful step may reuse only if inventory, database and every recorded result hash still match. Missing or modified sealed output fails. Unsealed nonempty stage output fails and is retained. Crash/cancel before atomic commit leaves no completed receipt; recovery cannot relabel the partial output as complete. `--limit` reports the full denominator and complete=false unless full selected scope was processed. `Seed` must never fall back to mutable upstream for an absent immutable snapshot.

HTTPS is the production transport. Explicit fixture file transport is test-only and must be rejected without the fixture allowance. Gitiles TEXT uses strict base64 after whitespace normalization; every resulting byte sequence is verified before publication. Temporary 429 retries use original URL and Retry-After; other errors fail without a different URL or looser pin. Retry/backoff, clock and cancellation are injected and tested without sleeping. Existing canonical restoration uses at most three attempts and at least one-second pacing; generic rehydration currently lacks this 429 policy. One service must expose the accepted profile's declarative retry policy rather than duplicate acquisition loops.

Metadata ranges require HTTP 206, exact Content-Range/length, identity encoding and unchanged ETag when available in the pinned metadata receipt. Canonical restoration additionally pins repository XML exact package path and archive size. The generic rehydrator's RangeReader lacks If-Match/ETag validation. This is a known source behavior difference, not evidence that weaker metadata acquisition is sufficient for the C# profile. Without an ETag receipt the member SHA remains mandatory and whole-archive identity remains unproven; do not invent a full archive hash.

Metadata read bound is 8 MiB per request; selected member compressed size at most 8 MiB and uncompressed size at most 32 MiB. Source-data archive download is bounded at 64 MiB in canonical restore and verifies SHA-256 plus published SHA-1. Only the existing name allowlist is selected: source.properties, sdk.properties, package.xml, api-versions.xml, api-versions-versioned.xml, annotations.zip, public.xml, attrs_manifest.xml, optional.json, AndroidManifest.xml. No android.jar/native library reading or SDK install/license operation.

Historical cache gzip bytes may differ despite equivalent records. Strict mode fails before publication. Permissive derived mode records original historical compressed hash, new compressed hash, recipe/source/producer pins and record count in a sidecar. Reuse validates all fields and actual bytes, and never claims historical registry identity. Migration must retain originals and write a new generation. Legacy cache readers accept only Java and SDK API-index cache producers; additional extractor formats must get explicit identities, not silently inherit these fingerprints.

## Extractor parity inventory

- Java: `java_source.py`, `java_context.py`, `jvm_source_link.py`. Preserve packages, explicit imports, unresolved wildcard imports, nested dotted owner and `$` binary owner, record components, compact constructors, enums, annotation declarations, overloaded methods, per-declarator arrays, receiver parameters, varargs, raw initializers and excerpt flags. Exclude method-body/local/anonymous implementation declarations. Keep implicit interface visibility distinct from permission/API membership. Preserve AST ERROR/missing-node unsupported records with byte ranges/line/excerpts and retained complete bytes. Explicit imported annotations and known android.annotation wildcard names have resolution evidence; other wildcard/type-variable resolutions stay unknown. Depth>128 is an issue, not silent omission.
- Signature text/AIDL: `parsers.py`, `foundation_extract.py`, `aidl_lex.py`, `aidl_members.py`. Preserve top-level separators outside comments/strings, quoted delimiters, nested bodies and exact repeated-line locators. AIDL declarations include interface, parcelable, union, enum, external parcelables, constants/fields/methods, directions, annotations, oneway and exact raw declaration headers. Shift/comparison angles are not generic nesting. Declaration/field ordinals are never wire tags; no expression evaluation. Reconcile independent lexical declarations/statements against produced records; unknown statements and unbalanced bodies stay visible.
- HIDL: `hidl_source.py`. Package/version is mandatory source context, not Android availability. Preserve imports, nested interface/struct/safe_union/enum/typedef, compound fields, annotations, template argument commas, enum shift expressions, method parameters/results and oneway. Oneway+generates is unsupported, missing package/semicolon/nested unsupported interface remain raw issues. source_complete=false even after structural success; no compiler/type-resolution/inherited-method/wire inference.
- SDK API XML: `sdk_api_index.py`, `sdk_availability_evidence.py`. Require explicit numeric target major.minor and root api/version4. Parse JVM arrays/objects/primitive/void descriptors conservatively; retain invalid descriptor as unsupported. Keep all historical/future/removed declarations with lifecycle status; exclusions are diagnostics, not dropped records. Preserve class/member inherited lifecycle and SDK extension tokens; malformed/undeclared token stays unknown. XML physical line numbers must match source. Index lacks field types, exact Java type kind, modifiers, constants, generics, throws and permission annotations; never invent them.
- Annotation ZIP/XML: build annotation path plus `annotation_link.py`. Preserve every raw item and parameter ordinal, unresolved/orphan/unmatched records. Exact qualified JVM key links only known owners/types. Generic outer erasure requires known-class proof; type-variable bound erasure and guessed java.lang names are forbidden. Legacy abbreviated signature fallback requires same repository commit and explicit platform version plus shadow checks on owner and member formals. Separate 37.0 annotation archive from 37.2 Java/index snapshot.
- Manifest/permission facts: `manifest_source.py`, `permission_reference.py`, `foundation_extract.py`, `scoped_permission_alias.py`, `permission_reference_evidence.py`. Namespace-aware manifest permission/permission-tree/group/uses-* facts retain raw attributes and physical lines. Permission AST supports permission/all/any/access/conditional/manual/explicit-none/unknown and all unresolved expressions; absence is not explicit-none. HTML parser retains named constant sections, duplicate/missing/ambiguous literals, lifecycle/protection raw metadata and unclosed sections while ignoring scripts/styles. Reference facts, constant values, manifest definitions, OS grants and MCP client permission grants are distinct authorities. Alias resolution is source-scope aware and must not borrow another version's manifest/constant evidence.
- Soong/interface: `interface_module_facts.py`, `interface_module_linkage.py`, `interface_hash_facts.py`, `aidl_frozen_hash.py`, `aidl_source_constraint.py`, `hidl_source_constraint.py`, `interface_applicability_evidence.py`. Static literal properties only; duplicate properties, expressions, defaults/filegroups/product selection remain unresolved. Literal srcs/exclude_srcs match repository-relative paths within same repository/revision. Build module identity, frozen AIDL version, HIDL package version, platform API and APEX version are separate domains. Preserve ambiguous/no module links, development-current dump unknown version, ordered duplicate published hashes and unknown hash lines.
- Frozen AIDL hash: sorted canonical `.aidl` paths; SHA-1 per source followed by `  ./<path>\n`; final seed is latest-version for version1 else previous positive frozen version plus newline. Require complete exact membership. Published algorithm selects last nonempty hex40 line; interface constraint additionally checks physical last-line backend semantics and exact source/hash/build linkage. These policies must remain separate rather than merged into one last-line helper with a single behavior.
- APEX: `apex_manifest_facts.py`, `apex_metadata_inventory.py`. Comment-aware JSON retains strings and duplicate-key ambiguity; version code permits 0 through Int64.MaxValue or canonical decimal string. Booleans, negative/overflow/placeholder versions remain raw unknown. Link only explicit safe literal manifest property; defaults do not prove linkage. Placeholder0 never becomes installed applicability.

No compilation/preprocessing, endpoint registration, transaction schema, lifecycle, permission-free or installed-version conclusion.

## Strict DRY compatibility policy

Inventory measured 27 frozen release011 tooling modules; 23 equal current candidate and local canonical bytes. Four differ. `build_catalog.py` candidate adds inherited interface_oneway metadata and changes the historical HIDL evidence scope list. `device_resolution.py` adds available-document-pin rejection. `dispatch_manifest.py` changes unavailable/inactive/nonbinding filtering and document validation order. `restore_snapshot.py` changes branch order only, with the same outcomes. Four source-facts modules are also byte-identical copies of canonical modules: callback_source_facts, functional_source_facts, interface_applicability_evidence, sdk_availability_evidence.

Keep one extractor/build/resolver implementation. Express observable legacy deltas in immutable `ProducerCompatibilityProfile` data: profile id/version, inherited-oneway inclusion, retained evidence scope set, available-document-pin requirement, and dispatch availability policy. Current hardened policy is default for new generations; release011 semantic reproduction is explicit and never silently promoted to current runtime availability. Do not encode branch-order differences as profile flags. Profile selection participates in fingerprints and generation/receipt identity. Schema/requirements/producer-file pins remain data evidence, not executable Python. Original local files remain intact until operator authorizes disposal. The port cannot claim original Python/gzip/database byte identity.
