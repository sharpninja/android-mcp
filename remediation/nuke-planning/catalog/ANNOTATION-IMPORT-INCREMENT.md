## Ownership and shared seams

- Sources owns ZIP/XML reading, raw annotation evidence, source-spelled target parsing, JVM encoding/key production, formal/header lexical facts, permission AST production and AIDL parse/lexical metadata. Catalog must not copy an XML, annotation, generic-type or JVM parser.
- Catalog owns snapshot eligibility from imported rows, exact target lookup, ambiguity decisions, evidence attachment, source_metadata_reference storage/validation, permission/declaration variant composition and canonical registry publication.
- The one Sources dispatcher currently does strict UTF8 preflight and cannot treat a binary SDK annotation ZIP as ordinary text. Sources must add an explicitly declared binary-source route or use an acquisition-unwrapped typed XML concern boundary. No extension guessing or replacement-character decoding is allowed. The managed factory registration extension also needs its own mocks.
- Catalog consumes the already native-proven shared SourceTypeFacts, JVM linker, permission facts, SourceXmlFormatter, canonical serializer and CatalogContracts. Raw XML child rendering has one Source authority. No second formatter or old-producer fingerprint is added.

## Locked import behavior

1. Stage source records/concerns losslessly. Source-owned AIDL metadata must expose the original full raw schema, root/declaration inventory, imports, locators, parse status and unknown wire/codec status. Catalog inserts this into aidl_schemas with named parameters. A malformed declaration remains explicit unknown evidence; no descriptor, transaction or codec is invented. Add the exact `package a; @Broken( interface IFoo {` original fixture before production.
2. Build symbol evidence in a separate pass so source ordering cannot change permission resolution. A symbolic constant resolves only when all retained values for that symbol agree. Keep manifest definitions, documentation symbols, OS authority and MCP client grants separate.
3. Import all SDK index lifecycle records. Build the current-target JVM owner/key lookup only from records whose lifecycle status is absent/current-at-target. Reject missing, inconsistent or mixed target-platform evidence as the preserved producer does. Source Java -> JVM linkage uses the shared JVM source linker and exact imported key, preserving a separate source-spelled Entry and its evidence. No public membership is inferred from visibility.
4. Retain every annotation archive member/item/annotation/val and raw XML through the Source concern producer. Preserve archive member name, item ordinal, annotation ordinal and parameter scope. Non-XML/malformed members become explicit retained issues. A missing/ambiguous target retains annotation_evidence with a null binding and a reason.
5. Attempt current SDK index exact target, then the Source-owned proven JVM erasure key. Only when the annotation platform has no imported SDK index may the legacy signature fallback run.
6. Preserve the exact distinct legacy fallback predicate from `same_snapshot_source_ids`: eligible declaration rows are **sdk-signature only**, and annotation/source must have the same nonempty repository, revision and platform_api_version. This is a three-field annotation eligibility rule. It is not the five-field type-resolution snapshot tuple and must not be broadened to source-signature or arbitrary repository evidence.
7. For fallback return/field types and java.lang shortening, inspect only eligible occurrence documents and their exact same-source owner header. Type and method formal names come from the shared Source helper. A shadowing formal, missing header, disagreement or multiple targets prevents attachment. Keep constructor return semantics and package-namespace cases from the original fixtures.
8. Preserve per-parameter annotation evidence without adding it as a declaration-wide permission. A known declaration-level external AST can add a permission relation. Unknown external metadata stays retained evidence and never becomes permission-free.
9. Merge discovery permissions with the original semantic rule that ignores x- fields for comparison. Distinct known expressions produce explicit source-dependent conflict. Known metadata plus absence evidence preserves each variant's x-occurrences and x-absence-of-annotation. Keep every immutable occurrence as the authoritative evidence. Source-dependent declaration shape/modifier evidence also remains explicit; any additional lexical modifier helper belongs to Sources.
10. Attach source references and variants before Entry/inventory document hashes. Use the one contract and projection engine. Validate all schemas, source references, target FKs, inventory dependencies and export/database agreement before publication. Alias default deny and unavailable dispatch remain unchanged; this metadata establishes no runtime authority.
