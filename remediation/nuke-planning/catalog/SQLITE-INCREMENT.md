# Native SQLite foundation increment

FR-BUILD-004/ac-1/ac-3 and TEST-BUILD-004; canonical SQL reuse also covers FR-BUILD-003/ac-2. This is the first durable-storage increment, not a claim that view activation, metadata CRUD or wire-proof services are complete.

The service will open a private in-memory SQLite database and execute the existing canonical Entry, Bridge or source-metadata DDL. Combined profile executes all three in one connection. Canonical SQL is read directly, never copied into a new schema implementation. Schema initialization completes before a connection is returned; failures dispose it. Original SQL files are never modified.

The test seam executes exact SQL commands and returns rows or SQLite's primary constraint error19. Independent scripts preserve assertions from test_contract_models.py, test_remediation.py and test_source_metadata_crud.py: FK enforcement, closed enums, append-only sources/bindings/registry entries, legal state transitions, history retention, metadata schema/id/reason checks, imported content pins and next-revision head CAS. Natural primary-key inspection runs over every SQLite table. Correct mocks verify every requested command and consumption. Negative controls corrupt each response at each command position individually.

Only after a green mock gate will CatalogDatabase implement the native provider. The SAME scripts and assertion function then bind real Microsoft.Data.Sqlite. These are fixture databases only. No devices, profiles in a live database, credentials or external services are changed. View activation/invalidation, protected metadata owner/schema/reference service behavior, wire-proof revision services, migration copies and the full catalog builder remain later increments with their own mock gates.

The46 mock instances passed before factory implementation in the130-test gate recorded by `evidence/sqlite-mock-gate.json`. Native bindings preserve all23 scripts and assertions. Microsoft.Data.Sqlite supports named parameters only ([Microsoft documentation](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/adonet-limitations)); the test transport maps the legacy fixture's positional markers to named markers and binds the unchanged values. The production facade accepts named parameters directly. Canonical SQL fixtures are hash-pinned in the real provider. The native gate is pending.
