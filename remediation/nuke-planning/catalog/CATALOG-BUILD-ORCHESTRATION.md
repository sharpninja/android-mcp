This is the remaining Catalog critical path under FR-BUILD-004 and TEST-BUILD-004/007. One app and one registered operation invoke these services; no second CLI, parser, hash engine or per-profile implementation is introduced. Prior preserved producers and profiles remain immutable inputs, not native proof.

## Locked service sequence

1. Validate the inventory/catalog metadata and select downloaded sources. Registry/api levels are actual positive integers; source api level is positive or explicit null, channel is nonempty, annotations require explicit platform version, and HIDL source release context never becomes Android applicability. Reject a nonempty output before any artifact write. Root's ArtifactPaths/FileLease controls all output ancestry and leasing.
2. Read each source through the Sources-owned dispatcher with the explicit legacy kind/scope mapping. Verify raw SHA256 and exact Git blob framing using the shared hash authority. Verify caches and native processing provenance through existing source services. A native C# processing/source identity is labeled separately from historical Python producer identity. Record unrecognized/unsupported concerns without guessing declarations.
3. Create one private staging SQLite catalog from the retained schema through CatalogDatabase. Normalize each declaration row once into an Entry, canonical identity and immutable occurrence; insert all source/details/report/issue/evidence records with named parameters. Permission AST/symbol extraction and XML rendering come from Sources-owned seams. Raw permission definitions, source relations, client grants and OS authority remain separate concerns.
4. Build snapshot-scoped type indexes and normalize each occurrence with CatalogProjection, SourceTypeFacts, CatalogContracts and CatalogLifecycle. Fields remain tied to their exact source occurrence; type dependency selection must have one exact snapshot contract. Header/formal parsing is never copied into Catalog.
5. Select a conservative discovery document per identity using the original source-rank policy, preserving all occurrence provenance, source-dependent declaration variants and permission variants/absence evidence. Attach source occurrence metadata before effective record hashing through the single Catalog metadata service. Produce the complete immutable registry inventory from the same projected documents and contract authority.
6. Validate every Entry, permission expression and inventory entity against its retained contract; reconcile binding/entry/occurrence/declaration/inventory counts, source references, canonical hashes and dependency pins. Run actual SQLite integrity and foreign-key checks. Fail with an explicit unpublished receipt and retain private staging evidence; never publish a partially validated registry.
7. Seal through staged -> validated -> published and select the singleton active registry only after all import checks pass. Export canonical deterministic JSONL tables, ordered Entries and inventory, inventory manifest, streamed catalog JSON and validation receipt. Generate offline aliases with default deny through the single dispatch manifest service. A source-derived codec candidate remains unavailable until independently proven runtime authority/codec requirements exist.
8. Produce catalog.sqlite as the final publication marker by copying the closed, verified staging database and verifying bytes. Retain its source staging copy outside the final artifact set under the leased private stage area; do not move or delete prior originals. The final manifest records the separate C# producer fingerprint and exact exported artifacts.
