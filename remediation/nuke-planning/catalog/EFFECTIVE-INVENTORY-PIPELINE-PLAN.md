Scope: the remaining Catalog portions of FR-BUILD-004 and TEST-BUILD-004/007, using preserved `test_effective_device_inventory.py` (five methods) and `test_device_catalog_pipeline.py` (seven methods) as literal assertion inventories. This is a staged decision-complete plan, not implementation, gate acceptance or a claim of historical equivalence. Source owns SDK/AIDL extraction. The existing native projection, contracts, lifecycle, resolver, storage, canonicalization, hashing and artifact store remain the only authorities for those concerns.

## Existing proof and missing caller behavior

CatalogBuild now captures one source window at a time into private SQLite and publishes a complete selected-registry projection through the shared streaming store. Four cursor cases plus Build7, SourceIntegration4 and actual registered CLI7 passed in the 20261028T0424232640492 gate. That does not prove local overlay composition, checked loading of an earlier registry, selected-view aliases or view-aware admission. DeviceResolver already preserves catalog_state, catalog_revision and catalog_document_sha256; DeviceViewStore already pins full inventory and activates sealed snapshots atomically. PolicyReference currently implements only the base binding/entry admission intersection. CatalogAliases currently generates default-deny offline aliases without a selected view.

It receives the existing CatalogDatabase, CatalogContracts, DeviceResolver, ICanonicalJson and Entry schema path. No parser, crypto, resolver, projection or artifact store is copied.
2. The parent approved additive CatalogDatabase.OpenExisting(path, readOnly=true), using read-only by default. It delegates to the existing Open implementation with no scripts and ReadWrite/ReadOnly mode, never Create. A separate mock gate precedes that factory addition. Missing files fail without creating an empty SQLite file or parent directories. Existing bytes remain unchanged by admission. No raw SqliteConnection factory or second schema/open engine is added. Seven staged scenarios cover default/explicit read-only, explicit read/write with rollback, missing default/read-write and malformed default/read-write existing files; every reply field gets an individually wrong control.
3. CatalogAliases adds a trusted-status overload to its existing engine; the current no-status overload keeps its exact behavior. It uses DeviceResolver snapshot validation and common canonical hashing rather than implementing another snapshot validator.
4. PolicyReference adds typed canonical route resolution and view-aware admission around the existing Evaluate algebra. A raw grant extension is separately allocated from the preserved policy test inventory; the five effective-inventory fixtures must not be used to claim complete unknown-raw policy coverage. No route may execute Android, infer transactions/codecs or confer OS/client authority.
5. Existing source/type/header facts, CatalogContracts.EntityKind/Digest, CatalogProjection.Incomplete and DeviceResolver.InventoryDigest are reused directly. No Source facts move into Catalog.

## Checked immutable loader

The loader requires catalog_meta.device_resolution_contract_version exactly2.1.0. It compares registry_inventory and registry_entries membership counts for the selected registry and rejects an incomplete projection without synthesizing rows. Every raw inventory JSON document is schema validated, must agree with its entry_id column, and its exact stored UTF8 bytes must agree with record_sha256 through common ContentHash.Sha256. Rows are yielded in entry_id order. Read-only loading may enumerate under the caller-owned capture transaction; it must not commit or roll back that caller transaction.

The independent export validator remains a distinct contract: reconcile each loaded item with the hashed Entry's projection, source evidence IDs, type dependency hashes, exact inventory stream and manifest registry/count/hash. It consumes the same loader and contracts, not a second projection implementation. Corrupted export or database rows never become a successful validation receipt. Its original nonmutation assertions remain mandatory and it writes its report outside the supplied sealed output tree.

## Atomic effective capture

Capture owns its read transaction and refuses an already active transaction. It reads active_registry plus catalog_view registry_generation/overlay_generation and the complete immutable base inventory. All base entities remain present, including suppressed imported Entries. The result includes registry_id, catalog_generation, overlay_generation, base_inventory_count, document_hashes, inventory and inventory_sha256.

Overlay rows are read in entry_id order. Each active overlay must pass Entry schema validation, agree with its SQL key, and have the common SHA256 of canonical_signature equal that key. Imported inventory is never rewritten. An active local addition gets an entity with no imported applicability evidence; deleted/conflicting local tombstones remain visible as other/empty variants without an invented shape. Every overlay state/revision is retained separately from version existence. Document pins use immutable record_sha256 for imported documents and canonical JSON SHA256 for overlay documents, including tombstones.

A changed AIDL structured field updates the enclosing imported/changed parcelable/union/enum shape using the exact owner/name match. Missing producer shape fails rather than inventing one. Recompute contracts only through CatalogContracts.Digest. Dependency reconstruction considers arguments, return type, structured fields and supertypes, plus a unique containing type for non-type Entries. Primitive references do not add dependencies. Missing, ambiguous or unresolved type evidence changes applicability to explicit unknown through the shared Incomplete helper. Local additions retain unknown imported availability. Unchanged entities update dependency pins to changed types. All final entities carry catalog_state/revision/document pin, pass InventoryEntity validation, are sorted by entry_id and receive the shared inventory digest. Commit only after every result field is established; exceptions roll back the read transaction and leave no writes.

## Trusted selected aliases and policy

A trusted status is supplied by a configured DeviceViewStore read. The fixture seam never accepts it as unvalidated request JSON. Missing snapshot, stale status, generation/epoch mismatch, invalid Snapshot or incorrect view_id hash fails closed. Selected aliases require exact inventory membership: every supplied Entry has a corresponding row and no extra row exists. Validate canonical identity and duplicate IDs as the existing engine does. Only available, active bindings get aliases. Their schema_hash and type_graph_digest come from the selected row; the row's catalog_document_sha256 must equal the actual current effective Entry hash. Keep full binding hash names, shared binding.invoke policy_tool_id, default_grant deny and dispatch_state unavailable.

Generated and generic requests resolve to the same CanonicalBinding tuple after schema pins agree. Known raw requires an explicitly supplied validated wire mapping and decoded canonical arguments; it cannot bypass the binding path. Unknown routes or stale mapping/schema fail. View-aware admission checks selected binding kind/schema/target and current effective document pin, then traverses dependencies with a visited set. Every traversed node must be available and catalog-active. Finally call the existing PolicyReference.Evaluate, preserving deny, os-unavailable, ask and admit-candidate. Metadata admission is never execution or an Android permission grant.
