# Atomic device-view persistence allocation

FR-BUILD-004/ac-1/ac-3 maps through TEST-BUILD-004; clean reconstruction contributes to TEST-BUILD-007. Preserve the eight assertions groups in test_device_view_storage.py and the lifecycle assertions in test_device_resolution.py. Inputs are trusted captured-fact fixtures and the complete immutable inventory, with no Android probes or connections.

One DeviceViewStore uses CatalogDatabase and DeviceResolver. It validates the complete snapshot against a fresh resolution from the trusted pinned inventory, then stores captured facts, a staged header, complete normalized membership and graph edges before sealing and atomically switching the active pointer. SQLite owns the final transaction, scope, inventory, generation and epoch guards. No second resolution or graph algorithm is introduced in storage. The canonical JSON and ordinary hash services define all stored identities.

Mock allocation before implementation: startup stale generation zero with complete inventory pinned; expected-count mismatch; duplicate or malformed inventory; complete two-node activation with one binding projection and one type edge; invalidation preserving the old immutable snapshot and recording its reason; stale captured facts; fresh epoch activation; current-generation CAS rejection; valid-hash cross-target and cross-profile rejection; changed catalog and overlay pins; partial or forged inventory membership; changed selected contract; inconsistent normalized row JSON; incomplete or unavailable transitive type graph; snapshot/facts/graph hash corruption; sealed-header/member/edge and active-pointer SQL guards; empty invalidation reason; reopened scope inventory mismatch; distinct reader/scope ETags; owner refresh precondition order; bounded header status; input/output copy isolation; integer epoch/generation exhaustion before mutating any catalog pin; and rejected caller-owned transactions.

Each scripted case asserts the full public fixture result plus privileged row counts, selected pointer and generation, membership projections, graph edge count, immutable prior snapshot, reason history, rollback state and foreign-key integrity. Correct mock responses and individually wrong fields at every call position must pass the discriminator harness before production. Independent literal canonical snapshot/facts/inventory fixtures supply expected hashes; production resolution must never generate its own expected output. The same cases and assertion function later bind the native SQLite provider.

The existing pure resolver cases prove availability projection and dependency closure only. They do not prove this lifecycle or persistence allocation. Keep both kinds of evidence distinct. No DeviceViewStore production is authorized before its own recorded mock gate.
