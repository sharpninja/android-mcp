## Reuse and exact profile distinctions

Extend the same native validator engine with the additive repository interface/overload after mock proof. Keep existing GeneratedDesign interface, expected cases and behavior intact. Reuse the private XML reader, six-tag HTML start-tag reader, checksum grammar/receipt hash and shared `IArtifactReferenceResolver`. No second generic parser, entity decoder, hash implementation, filesystem loop or source-routing map.

Repository Markdown uses the original `\]\(([^)]+)\)` token pattern, including an orphan closing bracket without an opening bracket. It examines every admitted path ending exactly `.md`, except paths with an exact `.git` component. It invokes the proven RepositoryMarkdown resolver: trim angles before fragment removal, ignore any URI scheme, percent-decode once, preserve plus/query text, allow a declared file or directory target and confine local references to the admitted namespace. The empty logical root can be a directory. The validator cannot infer an empty directory from a file list, and cannot decide whether an unadmitted target exists on the host.

Design checksums are interpreted relative to the explicit design prefix and always required, matching the original checker rather than the GeneratedDesign BeforeManifest phase. Reuse the already explicit malformed/duplicate/self/path diagnostic policies and examined-row count. Empty or partial checksum data does not establish emission completeness.

Only docs SVGs under the design prefix are counted and XML-parsed. The original Python branch did not require an exact expected set, SVG root/namespace/vector text or raw raster/script/SRC checks; do not silently apply GeneratedDesign-only rules here. Reuse the same BCL XML reader with the existing prohibited-DTD/no-external-resolver boundary and retained per-file diagnostics, declaring that boundary explicitly. Top-level editable ui-svg files are compared to same-name docs/screens bytes; derive these pairs from actual admitted editable files, without a model-ID requirement or an invented missing-editable assertion.

Offline presentation HTML uses the same six parsed asset tags and shared RepositoryOfflineAsset policy. Do not apply the Gradle raw HTML/CSS scan, embedding counts, Mermaid rejection or model/manifest checks in this profile. Thus uppercase HTTP values and CSS remote text retain the original Python behavior; lowercase http:/https:/protocol-relative asset attributes are errors. Duplicate attributes and a single entity decode remain observable.
