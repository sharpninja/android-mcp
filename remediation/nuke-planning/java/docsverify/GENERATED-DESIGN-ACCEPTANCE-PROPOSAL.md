## Boundary and authorities

`IGeneratedDesignValidator.Validate` receives a closed admitted artifact union, the already parsed `DocumentationModel`, its admitted DSL and UI manifest artifacts, and an explicit BeforeManifest/AfterManifest phase. The result scope is always `generated-design`. It cannot claim a repository scan. Repository Markdown scope and historical fixture publication changes are excluded from this increment.

The future pure implementation receives the existing `IArchitectureViewIndexReader`, `IArtifactReferenceResolver`, `ISourceHtmlDecoder` and `IArtifactReceiptVerifier`/shared content hash. The source collector owns source selection, files and directories. There is no validator filesystem access, process, network, source write, new blueprint/DSL parser, entity table or hash implementation. BCL XML parsing and a bounded HTML start-tag reader are syntax handling, not a new package dependency or browser parser.

The DSL and UI manifest must be present byte-identically at their declared paths in the union. Paths use the existing pure ArtifactPaths admission; duplicate/unsafe union paths are errors. The model is the same instance provided by the existing reader, never reparsed inside this service. Input artifact bytes, order, media types, model nodes, index relationships and request fields remain unchanged after validation.

## Exact phase and result semantics

BeforeManifest requires no checksum artifact and reports ChecksumsChecked=0. An already present checksum artifact is a phase error, rather than silently becoming a validation prerequisite. AfterManifest requires `docs/checksums.sha256` and validates every line. Neither phase writes a checksum or changes the artifact set.

Counters preserve the original four names and meanings within this bounded scope: checksum lines admitted for checking; nonempty non-URI Markdown file references examined; actual docs SVG artifacts, including malformed ones; actual top-level ui-svg artifacts. A failed target still increments its corresponding checked counter. A malformed checksum row counts as one examined row, a defined diagnostic extension to the old command's exception behavior. A final newline is not an extra row; interior blank lines are malformed rows. Counter differences caused by a removed artifact or added link are asserted explicitly.

Expected and actual docs SVG path sets are independently returned in ordinal order. Missing/unexpected members are reported separately. Stable `DesignIssue` codes/path/subject fields are compared exactly. BCL XML parse diagnostics retain path, line, column and nonempty framework message separately; the test checks those facts without comparing localized exception prose. Diagnostic order is rule order below, then ordinal artifact path, then source occurrence/manifest line. An input/path/manifest admission error prevents dependent checks whose prerequisites cannot be trusted; unrelated artifact checks still retain their own errors.

## Rule order and acceptance cases

The case IDs below describe authored inputs and expected outcomes, not runtime readiness claims. Every positive expected value and every asserted field has an independent incorrect-response control before the same cases bind production.

1. `DV-INPUT-*`: safe unique paths; duplicate same/different bytes; parent/root/backslash paths; missing/substituted DSL or UI manifest; unsupported phase. Require stable input diagnostics. Null API arguments remain programmer errors. No filesystem probing is available to the provider.
2. `DV-MODEL-*`: strict UI manifest JSON, including malformed/duplicate/invalid UTF8/hidden semantic fatal vectors reused from shared strict JSON cases; model screen/storyboard identities agree with the manifest; declared state/step variant paths are safe, unique and complete for the supplied model. Reuse the model's IDs/state specs/story steps and manifest roles, never a numeric screen/view range. Native view duplicate keys remain visible and produce a duplicate-view error. Native diagram names follow the existing composer convention; code-image paths come directly from the shared view index. The complete expected set includes all native/code/UI overview/state/step outputs.
3. `DV-SET-*`: minimal positive set, reordered input, missing/extra architecture SVG, missing/extra overview SVG, missing/extra variant SVG and extension/case boundary. Each test checks exact expected/actual path lists and actual count, not a minimum. A missing item must not be removed from the expected set to make the case pass.
4. `DV-XML-*`: valid vector XML, malformed XML, DTD/external entity, wrong root, wrong namespace, missing vector text, raster image, script, stale SRC metadata and multiple failing files. DTD processing is prohibited, external resolver null. Parse failures retain actual-file count and a per-file parse diagnostic. Current Gradle raw case behavior for SRC and raster/script markers remains an additional check; XML parsing does not silently replace it.
5. `DV-LINK-*`: current Markdown selection is exactly docs/**/*.md, contracts/**/*.md, README.md, storyboards/storyboard.md and architecture/code-diagrams.md. These mandatory root/deck/code source paths must be admitted. Test file target, fragment, angle/fragment order, literal percent encoding, literal query, URI/data exemption, unsupported colon target, directory-only/missing file target, namespace escape and an out-of-scope Markdown artifact. Use the proven GradleMarkdown reference profile for every extracted target. All links in selected current source text count, including text in fenced blocks, matching the legacy regular expression. Mermaid fences are rejected case-insensitively for selected current sources. An arbitrary historical fixture basename is never special-cased.
6. `DV-COPY-*`: model-derived editable pairs all match; missing editable member; missing docs counterpart; one-byte difference; unexpected editable member; nested ui-svg file boundary. Expected roles come from screen/storyboard model IDs. Top-level editable members are counted even when incorrect. The compatibility copies remain outside the docs SVG denominator.
7. `DV-HTML-*`: require the admitted docs/storyboards.html and storyboard Markdown. Test all six asset start tags script/img/link/iframe/video/audio, src/href, entity-decoded references, lowercase and uppercase values, protocol-relative values, local/data values, duplicate attributes, comments, raw script text, quoted `>`, and unrelated tags. Preserve both legacy rule families explicitly: the Gradle raw src/href/CSS URL scan and the repository start-tag asset scan over the bounded HTML artifact. A raw external reference and its parsed counterpart can produce two separately coded issues in deterministic order; no result deduplication conceals a failing rule. Core reference profiles preserve their existing case/decoding differences. This is not repository-wide Markdown coverage.
8. `DV-EMBED-*`: storyboard SVG references remain confined admitted file references. HTML raw `<img\s` count and exact double-quoted SVG data URI count each equal the storyboard SVG occurrence count; `![Screen]` is absent. Test each missing/extra image, residual Markdown, non-SVG data image, changed quotation/case and duplicate storyboard occurrence. These checks preserve the original count/embedding contract; they do not claim decoded-image equality or visual acceptance.
9. `DV-MANIFEST-*`: AfterManifest accepts the existing package builder's emitted checksum format; ordering changes with unchanged valid targets preserve per-line semantics. Test missing checksum, empty checksum (zero checked rows), malformed hash/separator, blank line, uppercase/short hash, unsafe/self/duplicate target, missing target, changed target bytes, space/Unicode target names, CRLF and final newline. Compare hashes through the common receipt/hash authority. Check every listed target; do not infer whole-union manifest coverage from a valid partial list or zero rows. Complete checksum emission remains the package builder's independently tested responsibility. BeforeManifest rejects a supplied checksum without hashing it.
10. `DV-ORDER-*`: multiple distinct errors across files and rules, reversed input order and repeated validation produce the same ordered result. Assert all counters, expected/actual paths, scope, phase, validity, issue code/path/subject and parse diagnostic fields. Controls independently omit/add/reorder each result list, change each counter/phase and mutate input bytes/model fields to prove the assertion harness rejects those errors.
