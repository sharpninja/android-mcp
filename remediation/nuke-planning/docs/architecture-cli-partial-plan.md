# Native Architecture CLI partial plan

The first actual CLI proof targets the current 21 architecture SVGs and six editable class PlantUML files. It does not claim complete legacy Gradle preflight parity: `validateModelContracts` remains an operational native port gap. That gap includes contract-copy pins, cross-artifact dispatch/revocation ordering, routes, control/state/storyboard contracts, and the legacy dependency from `validateArchitecture`.

Proposed registry request is `Design --operation Architecture`. Reuse `project-root`, `output-root`, `cache-root`, `receipt-root`, and optional `generation`. Add required `work-root`, `docker-identity`, `renderer-user`, and `tool-access`; optional `offline-gradle-checksum-proof` belongs only to the existing native bootstrap mode. For the first real generation select explicit `Online`, using the verified existing cache. The live canonical published Gradle checksum still must be fetched and verified by the approved native transport. No receipt is fabricated from the PowerShell cache inspection.

The staged planner tests bind the existing `IOperationPlanner` seam. They check exact required/optional parameter admission, missing/empty values, unsupported options, legal category, the single Architecture operation, unchanged input parameters, and zero observed effects. Their planned step vocabulary is `validate-architecture-inputs`, `preflight-native-context`, `verify-pinned-tools`, `generate-architecture`, and `seal-generation`, with one linear dependency chain. These are registry declarations, not a second execution graph or operational entrypoint. The root owns their approval, registry data, parameter declarations and Build dispatch.

The host preflight uses the existing shared root/path and ToolIdentity authorities. It admits canonical source and tool-cache inputs, separate fresh work and final output roots, a separate process receipt root, and the content-pinned native Docker identity. It resolves the PlantUML bind path from that same admitted cache root and the locked download path. The first supported renderer is the explicit local Linux Docker socket, with numeric renderer UID:GID. It must not select a cloud context, inherit Docker environment settings, pull images, invoke a shell, or execute Python/Node/Marp.

Composition is thin: bind source/work/final `FileArtifactStore` instances, shared leases/receipt verifier/manifest factory, and two instances of the one `ArtifactGenerationRuntime` protocol; construct the existing `NativeProcessRunner`, `ProcessCaptureReader`, renderer transport, native image admission, native bootstrap, native composer and existing recipe factory. Execute the Architecture recipe in the final runtime. The composer uses the work runtime for its 85-artifact work generation; the final runtime commits the 27 public artifacts with its manifest last. Reuse the canonical root lease identity across every category operation using the same destination. No new parser, generation loop, filesystem helper, hash implementation or lease implementation is needed.

Existing Gradle aliases remain registry compatibility data. The relevant names are `extractCodeViews`, `renderCodeViews`, `validateArchitecture`, `exportArchitecture`, and `generateArchitectureDiagrams`; preserve each alias's selected legacy stage semantics in the single union planner. `validateModuleGraph`, `validateModelContracts`, and `verifyToolchain` belong to the central Validate service vocabulary. The first full Architecture CLI proof does not by itself prove that all these aliases or their historical prerequisite subsets have been ported. Gradle must delegate the validated alias list once through `GradleCompatibility`; it must not retain its old dependency graph.

Runtime proof must retain the NUKE command/result, actual native process receipts, selected Docker ToolIdentity, the independently verified checksum proof, all five image file hash checks, Java/font admission, work manifest and final manifest. Verify the exact six editable and 21 SVG paths against the canonical model, all final artifact hashes/lengths, valid vector XML and the retained source hashes. Browser QA is a separate native component and must consume the committed final generation. A fake process integration or the historical saved SVGs cannot stand in for this execution.
