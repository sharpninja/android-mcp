# Remaining Gradle support payload

This is the remaining source-package duty after the native C# host payload proof, not a new build graph. Keep all category/alias/operation/parameter definitions in the existing NUKE registry and stage planner.

The portable package must also retain the generated `build.gradle.kts` and `tooling/nuke-design-stages.json`, existing `settings.gradle.kts` and `gradle.properties`, and `gradle/wrapper/gradle-wrapper.properties`. Wrapper executable/JAR source paths and pins come from the existing admitted renderer profile's non-cache downloads. Do not duplicate their hash/version table, include the Gradle distribution/cache, or discover source files by directory scanning.

Use a small pure support projection with mock-first path/coverage/pin cases. Capture these support files as configuration inputs in the existing main source runtime, with the same unchanged-byte check before commit. Append the captured artifacts to the existing child payload preparation before the existing validator, single checksum manifest and archive. Do not create another store, writer, package engine or checksum implementation. The C# native source collector and its two fingerprint rechecks remain authoritative for `build-tool/` sources; the separate project-root support files retain their own source identity.

The direct C# package path requires these committed bootstrap sources. A missing wrapper/source must fail explicitly. Tool acquisition remains the existing tools stage; this increment does not introduce silent network provisioning, SDK discovery or a fallback implementation.

The clean exported package proof must run the existing Gradle adapter with its required explicit host/project/renderer/root parameters, selecting a bounded existing alias such as `extractCodeViews`. The alias selection and ordering must still come from the shared C# planner. The native host bootstrap proof, artifact pin verification, archive coverage and old inactive/default package cases remain required. No complete migration, independent acceptance or Windows runtime claim follows from this bounded portability proof.

Implementation is staged separately while the checkpoint 012 full suite runs. No support projection implementation or mock gate is claimed by this plan.
