# Native Review composition

All process calls use the shared IProcessRunner and IProcessCaptureReader. All bytes use the shared IArtifactStore, lease provider, canonical JSON and content hash services. No Python, Node, shell wrapper or REST fallback exists in Review.

Construct ReviewAssessService with the shared SHA256 delegate. Construct GitReviewPrerequisiteSource with approved git identity, checkout directory, a private capture root, shared dependencies and ReviewPrerequisiteConfiguration. Inject this mandatory source into both ReviewPrepareService and ReviewLaunchService. Inject the live GitHubReviewReadinessSource into both. The source performs read-only exact-commit verification, NUL-delimited tree inventory and pinned project-definition reads. It never infers test identity from a filename.

ReviewPrerequisiteConfiguration pins three receipts by path and SHA256. The runtime composition must obtain these receipts from trusted native gate/official-plugin captures, not from caller completeness assertions. Every receipt binds the reviewed head. Evaluation provenance uses source native-project-evaluation and the verified native evaluation tool SHA256; projects contain path, definitionSha256, explicit isTestProject and kind unit/integration/none. Every project definition found in the Git tree must appear exactly once, including supported MSBuild, Gradle, Maven and package descriptors. Dynamic or unresolved metadata without a trusted evaluation receipt blocks.

The normalized official-plugin requirements receipt uses source required-mcp-plugin, plugin, pluginVersion, workspace, head, functional, technical, testing and mappings. Functional records contain id and nonempty acceptanceCriteria with id/text. Mapping records contain frId, nonempty trIds/testIds and criteria coverage entries with acId/testIds. Every scoped FR criterion must be covered, every target must exist, and all scoped TR/TEST records must map. Status and isSatisfied may remain pending/false until post-ready HV. They are not caller permission to omit records or mappings. These normalized bytes need provenance from the actual required-plugin response; source labels alone are not a trust authority.

The self-review receipt uses head, scope design-and-nuke-only, scopeIntegrationProjects and checks. Each check has code/path/sha256. The single authoritative list is GitReviewPrerequisiteSource.RequiredChecks. All nine entries and their immutable evidence are required; the integration list must match the explicit review plan. Inventory output is written immutably under reviews/{runId}/project-inventory.json.

Prepare verifies current GitHub PR open/non-draft readiness and exact head, trusted inventories, supplied unit/scope integration TRX bytes and run/host/head/command metadata, requirements evidence and public-only payload. It freezes exact inputs and returns PreparedReview including prerequisite pins. Launch reobserves readiness and trusted prerequisites, verifies all frozen hashes and exact reviewer capability, acquires one run lease and writes intent before process effects. ResumeAsync uses the same execution algorithm, replaying only bound terminal request/completion/visible-response prefixes. Missing terminal proof blocks without another process call. Output/context continuations have no assistant budget and retain every prior visible finding and range.

ReviewWorkflow.ExecuteAsync routes Prepare, Launch, Recover and Assess. Recover with a PreparedReview uses persisted replay/continuation; Recover with ReviewRecoveryInput only classifies/adopts an externally supplied terminal result and never invokes a process. Launch/Recover require exact Opus 5.5 XHigh capability and actual response metadata. A complete report is separate from accepted 98/98 AGREE.

IReviewAudit is mandatory and has no production no-op default. VerifyReadyAsync checks installed official Claude plugin identity/manifest/configuration pins and scoped session-log tool capability before intent/provider effects. RecordAsync returns proof from read-back of the actual reviewer's own turn after startup. RequiredPluginReviewAudit consumes IReviewAuditTransport, normalizes and immutably stores bootstrap/read-back proofs, and never creates a Claude turn through the Codex plugin. UnavailableReviewAudit disables provider execution when no trusted transport is configured. The concrete transport must use the root-approved typed official-plugin purpose invocation once tested.

Launch keeps built-in tools empty and enables only the verified private MCP configuration and allowed session-log tool names. Private configuration contents are never embedded in prompts or request receipts. The prompt carries run/call/head/parent IDs and requests the actual reviewer to author its own full turn. Final acceptance requires actual Claude identity/model/effort/session/request, full-verdict read-back and related-call coverage. Classification is provisional until this proof passes. No provider is launched during implementation, and the PR must be ready before any HV. Unit fake transport results are never live reviewer/MCP parity.

Implemented after their mock gates: stderr-only provider/capability pauses, unique immutable GitHub observation captures, quoted-JSON/bearer credential exclusion and finite JSON-number verdict scores bounded to 98..100 for acceptance. Their same-case native bindings and the eight audit native cases passed the 14,845-test scoped gate. Final JSON suffix parsing preserves progress and split message fragments, honors the latest verdict and never accepts an output cutoff; its four native cases passed the subsequent 49-test gate. The public prompt places end_marker inside the standalone final JSON object. See GATE-LEDGER.md for exact receipts and the pending current-head regression gate.

Runtime composition must keep provider execution disabled until the actual official audit transport/bootstrap capability is verified. The transport binding and category CLI composition remain root-owned gaps, rather than claimed live parity.
