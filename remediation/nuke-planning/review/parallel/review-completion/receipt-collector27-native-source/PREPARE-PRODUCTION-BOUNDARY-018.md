# Full Prepare and exact production audit boundary

This is a concrete integration plan, not a changed Review/Prepare meaning or an implemented positive CLI. The local audit_receipts.py collector is a separate receipt-integrity responsibility. Its metadata/completeness output is never PreparedReview, official source authority, model/effort verification or hostile acceptance.

Root's thin Review/Prepare dispatch keeps the existing six admitted project-root/output-root/receipt-root/pipeline-request/hash/length parameters and ReviewPrepareInputsReader. ReviewPrepareService remains the sole preparation owner. It must observe an OPEN/non-draft PR at the exact expected head and URL before the lazy trusted prerequisite factory runs. The factory consumes real current-head native evaluation/full-TRX/Git observations, required-plugin complete FR/TR/TEST/mapping/criterion evidence and actual nine-item checklist evidence. The new native/record projections preserve pins but deliberately do not mint source labels. Missing actual origin is PREREQUISITE_AUTHORITY_UNAVAILABLE; a diagnostic unavailable path is not positive completed migration. There is no local-only alternate Prepare status or empty/fake prerequisite source.

Production review launch/recovery audit binding is exactly:

`RequiredPluginReviewAudit(new OfficialPluginReviewAuditTransport(purpose, runtime, store, canonical, workspace, cumulative), store, canonical)`

The existing official adapter has no process/shell/network/mutation API. Its ObserveBootstrapAsync requires the actual pinned installation/runtime/config/tool/no-drain observations from IReviewOfficialPurposeInvoker.ObserveInstallationAsync. ReadReviewerOwnTurnAsync requires the actual provider-native runtime/effort/model and own-turn link from IReviewProviderRuntimeEvidenceSource, the exact persisted official page read from ReadReviewerTurnsPageAsync, and actual cumulative evidence when multiple reports require it. Requested argv/model strings, cached labels and self-authored JSON cannot populate those authorities. Cumulative acceptance stays bound to the same final provider call and full visible verdict. The reviewer authors its own complete ClaudeCode turn; Codex never writes or imports that turn.

The exact missing production capabilities are concrete. IReviewOfficialPurposeInvoker currently has no authorized verified exact-scope live runtime implementation; typed pages do not prove that an installed QueryAsync operation can enforce the requested run/session scope. IReviewProviderRuntimeEvidenceSource has no authorized current Claude Opus5.5 XHigh schema/runtime proof before Ready. The existing OfficialPluginReviewAuditTransport and RequiredPluginReviewAudit are implemented consumers, not factories that establish those observations. Do not substitute UnavailableReviewAudit as positive authority or install a no-op audit.

- The earlier broad effective-requirements read was denied. Do not replace it with list-all/effective/raw REST or broad query plus local filtering. Installed direct-record model documentation does not authorize live invocation or establish the undocumented response envelope.
- Actual reviewer capability/model/effort/audit and live positive Prepare remain deferred until Ready and explicit capability reconciliation. No reviewer/provider or HV runs in this increment.

Positive fake-only tests establish adapter behavior, never actual official authority. No new generic plugin infrastructure or competing orchestration is proposed.
