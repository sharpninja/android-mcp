# Native review migration

Scope: FR-BUILD-001..007, TR-BUILD-TOOL-001..007, TEST-BUILD-001..007. No requirement is marked complete. No provider call is authorized during implementation. Review only design and NUKE impacts. The PR must be ready before HV.

The first increment binds the 25 named ReviewCases to a scripted fake and verifies each status assertion and process-call assertion with individual passing negative controls. The mock gate runs through the root-owned NUKE test target, selecting ReviewMockGate. Production code is written only after a zero-failed, zero-skipped receipt. The same cases then bind to NativeReviewCaseSystem. Full unit/scope integration TRX and complete requirements are mandatory review inputs; reviewers never build or run tests.

Native services: Prepare verifies immutable evidence, head-bound readiness, requirements, unit/integration project coverage and successful TRX; Launch serializes calls under a lease, records exact request and full visible response, verifies actual model and effort, and continues known terminal output/context boundaries without a budget; Recover adopts completed work and refuses to relaunch active or uncertain work; Assess classifies terminal results and requires numeric 98/98 plus AGREE and zero FAIL/UNKNOWN before acceptance.

Legacy dispositions: hv_invariants.py becomes ReviewAssessService and ReviewPrepareService; hv_runtime.py and hv_runtime_opus.py become ReviewLaunchService using the shared IProcessRunner, without superseded Fable fallback; hv_supervisor.py becomes automatic terminal-only continuation in ReviewLaunchService; recover_design022.py and recover_design023_factored.py map to ReviewRecoverService plus exact evidence partitioning. Historical numbered review launchers remain immutable history with their round-specific payloads supplied as data to Prepare. audit_factored023_runtime.py, audit_review023_active.py, audit_review023_payload.py and audit_review_environment.py become native validation of hashes, coverage and public process metadata. test_hv_invariants.py, test_hv_opus_profile.py and test_hv_supervisor_integration.py provide source-pinned cases and additional native safety cases. Superseded bounded runners have no executable successor. Existing source and receipts are retained unchanged.

CLI seam: only shared IProcessRunner, absolute executable identity and argv boundaries; no shell, permission bypass, fallback model, assistant timeout/turn/word/output cap. Prompt stdin must be provided by the shared runner. Private profile/marker/credentials never enter review payloads. Hidden reasoning is discarded rather than logged; every visible event and malformed visible fragment is retained with provenance. Provider/auth/capacity failures pause immediately.

Runtime composition must provide the artifact store/root, leases, shared canonical JSON/hash service, verified CLI identity/capability receipt, live GitHub readiness source, mandatory trusted prerequisite source, process capture reader, and a required-plugin IReviewAudit implementation. There is no no-op audit default. Unit tests use an explicit fake audit and cannot establish live reviewer session logging. GitReviewPrerequisiteSource verifies the complete project-definition denominator and pinned native evaluation, official-plugin requirements and self-review receipts. Both Prepare and Launch require its head-bound inventories. Persisted crash continuation now replays verified terminal prefixes through Launch.ResumeAsync without repeating completed calls; requests without terminal proof remain blocked.
