# Minimum safe native Review/Prepare composition

Current implementation: ReviewPrepareService.PrepareAsync(ReviewSnapshot). ReviewWorkflow.ExecuteAsync routes Prepare with ReviewOperationInput.Snapshot. Root owns registry, Build and public argument decoding; this document changes none of them. Current registry still lists Review/Prepare as Pending with snapshot only. The proposed required arguments below make the existing service's actual dependencies explicit.

Required operation arguments:

- snapshot: canonical JSON file deserialized as the existing ReviewSnapshot, using the shared strict JSON reader. RunId is one safe path segment. ParentSessionId and ParentRequestId identify the actual requesting turn. Head is the full immutable reviewed commit. PullRequestUrl is the concrete PR. UnitProjects, IntegrationProjects and RequirementIds are complete scoped inventories, not completeness booleans. Evidence contains exact relative paths, SHA256 and kind; every TRX item also includes project/run/host/head/command.
- project-root: exact Git checkout and active workspace. It must agree with the prerequisite configuration's workspace and every trusted capture. It is the working directory for read-only git and gh.
- output-root: shared confined immutable artifact store containing the referenced evidence and trusted receipts; receives reviews/{runId}/input, readiness, manifest, prompt and prerequisite inventory. Reuse the shared store/path/lease implementation.
- receipt-root: separate private root for complete git/GitHub stdout/stderr process captures. Reuse shared process/capture services and unique observation directories.
- git-identity: the existing ToolIdentity JSON, pinning absolute executable path, SHA256 and version. Only the service's fixed read-only rev-parse, ls-tree and show commands are issued.
- gh-identity: the same ToolIdentity shape for gh. Only the fixed pr view request for isDraft/state/headRefOid/url is issued.
- prerequisite-configuration: the existing ReviewPrerequisiteConfiguration JSON. It specifies WorkspacePath, PluginName, PluginVersion, three path/SHA256 receipt pins (EvaluationReceipt, RequirementsReceipt, ChecklistReceipt), and the explicit ScopeIntegrationProjects list. These are trusted composition inputs whose native/official-plugin producer provenance must be verified by root, not arbitrary files accepted because their source label says trusted.

Global root/category/operation options remain root-owned. No reviewer executable, model, effort, MCP reviewer configuration, live audit transport or provider permission flag is needed for Prepare. It freezes evidence; it never calls IReviewAudit or a provider. Do not require the unavailable live reviewer binding merely to construct this operation. Do not add a caller ready/complete/HV-approved boolean.

Root constructs the existing shared store/lease/clock/canonical/hash services, GitHubReviewReadinessSource with pinned gh, and GitReviewPrerequisiteSource with pinned git plus the trusted configuration. It injects both sources into ReviewPrepareService. A narrow Prepare executor may call that service directly; it need not construct ReviewLaunchService or the entire workflow to prepare evidence. Normal mock cases should verify required arguments, typed decoding, missing/mismatched pins and no provider dependency before executable wiring.

The service CURRENTLY requires the live PR to be OPEN and non-draft, with URL/head exactly matching the snapshot, before freezing inputs. A draft PR returns PR_NOT_READY. This preserves the current fail-closed policy and the user's NO HV before Ready instruction. Preparing a preliminary package while draft would be a separate mock-first behavior change; this contract does not silently introduce it.

Trusted evaluation must cover every project definition observed by Git at that exact commit, with definition SHA256, explicit isTestProject and kind unit/integration/none. It cannot infer test identity from filenames. Unit TRX bodies must cover every discovered unit project; scoped integration TRX bodies must cover the explicit review plan. Required TRX metadata is head/project/run/host/command and an exact body hash from the implementing native gate. Root must bind that metadata/body to its actual gate capture; the present service validates supplied fields and bytes but cannot independently establish producer authority from caller text.

The requirements receipt must preserve complete actual official-plugin FR/TR/TEST/AC records, mappings and criterion coverage. Status/isSatisfied may remain pending/false until post-ready HV. Do not invent per-criterion mappings from complete=true or omit missing raw server fields. If normalization derives criterion coverage from an explicit TEST statement and real coverage evidence, retain that source provenance and exact raw response pins. Missing derivation evidence blocks.

The parent has forwarded a separate automatic-approval denial of workflow.requirements.effective before execution because its broad retrieval precedes BUILD007 filtering. Prepare must use already verified task-scoped requirements receipt pins. It must not invoke that same broad read indirectly through GetEffectiveRequirementsAsync, REST or another wrapper. Only a documented meaningfully safer server-side exact-ID route, or new user approval of a specific minimum scope, can change that boundary. Current wiring must preserve blocked/unknown rather than manufacture fresh requirements provenance.

The checklist receipt binds head, design-and-nuke-only scope, explicit integrations and the nine codes in GitReviewPrerequisiteSource.RequiredChecks, with each item's real evidence path/hash. Missing native evaluation, requirements or checklist provenance is an unavailable prerequisite, not permission to supply a fake positive.

Successful Prepare means only that the existing head-bound, public-only evidence package was produced. It does not mean provider/HV execution, AGREE, live plugin parity or requirement completion. Reviewer instructions remain: supplied full TRX, no reviewer builds/tests, no Google API/data analysis, no arbitrary shell/network, no assistant caps, complete visible receipts, actual own-turn audit after startup.
